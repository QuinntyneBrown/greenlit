# Greenlit: L2 requirements

Detailed requirements with acceptance criteria. Each traces to an L1 item. Tests cite the L2 id
and criterion they prove (`// Traces to: L2-001 AC1`).

Format:

```
## L2-NNN: Title
Traces to: L1-NNN
Status: Proposed | Accepted | Implemented

<one paragraph>

Acceptance criteria
- AC1: Given ..., when ..., then ...
```

## L2-001: Pipeline smoke endpoint

Traces to: L1-008
Status: Implemented

`POST /api/_ping` exercises validation, logging, the handler and the exception middleware so the
cross-cutting plumbing is proven before any feature endpoint exists.

Acceptance criteria

- AC1: Given `{ "mode": "ok" }`, when posted, then the response is 200 with `{ "message": "pong" }`.
- AC2: Given an empty or unknown mode, when posted, then the response is 400 `application/problem+json` with `title` "Validation failed" and an `errors.Mode` array.
- AC3: Given `{ "mode": "notfound" }`, then 404 problem details with title "Not found".
- AC4: Given `{ "mode": "conflict" }`, then 409 problem details with title "Conflict".

## L2-002: Application shell

Traces to: L1-007, L1-008
Status: Implemented

Every screen renders inside one `<main id="main">` landmark preceded by a "Skip to content" link,
and stamps its slug on `<body data-page>` so the e2e page objects can anchor on it.

Acceptance criteria

- AC1: Given any route, when it renders, then `body[data-page]` carries the route's `page` slug.
- AC2: Given any screen, when Tab is pressed once, then the skip link has focus and targets `#main`.
- AC3: Given `/`, then the app lands on `/sheet`.
