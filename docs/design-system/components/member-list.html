Member list

The settings list of everyone on the team: name and email, role, and yearly days, editable in the row by the manager.

Overview

The member list is where the manager manages the team in Settings: who the members are, who else is a manager, and how many days each has each year. Each row is one member with its own controls, so a change is made where the person is, not in a separate form.

The list is for editing. Reading the same people is a different job: the team grid for the month, the table for allowance across the year, a list for plain browsing. Members see the list read-only: controls are disabled and the manager is shown the same rows. Inviting and removing members open dialogs; they are never inline forms.

Anatomy

  1. AvatarAvatar of the member's initials; decorative.
  2. Who.member-list__who: the name as a link to the person page, and the email beneath. Both truncate with an ellipsis.
  3. Role selectA small select: Member or Manager. 8.5rem wide, with a hidden label naming the member.
  4. Yearly daysA small number field with the "days / yr" suffix; labelled with the member's name.

One row pattern. The row wraps its controls when there is not enough room.

Row-level states come from the controls inside it. A saving row disables its controls and shows a spinner on the pressed control; a failed save shows an inline message under the row.

Responsive behaviour

  • Rows are flex-wrap: wrap. The identity block grows (flex: 1) down to 10rem; the role select (8.5rem) and yearly days (about 9rem) wrap onto a second line under it on narrow screens.
  • At 360px the controls sit on their own line below the name, left-aligned; nothing scrolls horizontally.
  • Name and email truncate with an ellipsis rather than wrap, so a long email never pushes the controls away.
  • The list sits in the settings content column; at 64rem (1024px) the settings navigation appears beside it, which narrows the list but not its rules.

Theming

The list is a bordered surface: --color-bg-surface with a --color-border-default border and --radius-md. Names inherit the text colour; emails and the "days / yr" suffix read --color-fg-muted. Inputs and selects bring their own tokens, so disabled and invalid states follow the form theme.

/* Stack the controls on a narrow settings panel */
.member-list > li { align-items: flex-start; }
.member-list .select, .member-list .days-input { width: 100%; }

Accessibility

Role and pattern

A native <ul> of rows whose controls are native form controls. It is not a grid or listbox: each control is its own tab stop. The name is a link to the person page; the role is a native <select>; the days is a number input.

Keyboard

KeyAction
Tab / Shift+TabName link, then role select, then yearly days, then any remove button, row by row.
↑ ↓ on the selectChanges the role (closed select) or moves in the open list.
↑ ↓ in the days fieldSteps the number by one.
Enter on the name linkOpens the member's page.

Focus

The shared focus ring on each control. The name link is underlined on hover and ringed on focus; the select and input use the form control focus style.

Labelling

Every control repeats in every row, so every control carries the member's name: aria-label="Role for Ana Ruiz", aria-label="Yearly days for Ana Ruiz", "Remove Dev Patel". The "days / yr" suffix is visible text associated through the wrapping <label>. Give the list an aria-label such as "Members".

Motion

No row animation. Saving shows a spinner on the pressed control; it keeps turning under reduced motion because it is a status indicator.

Touch

Selects and inputs are 32px high in the list, above the 24px minimum, with 12px gaps. Wrapping gives each control its own full-width line on a phone so they are easy to hit.

Content

  • Name in full; email beneath in lower case. Invited members show "Invited 3 Nov · not signed in yet" instead of an email only when no email is known.
  • Roles are exactly "Member" and "Manager".
  • Suffix "days / yr" stays inside the label so it reads with the number.
  • Destructive removal is a dialog titled "Remove member" naming the person, never a bare icon.
  • Say who can edit: "Only the manager can change roles and allowances."
