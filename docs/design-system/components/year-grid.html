Component · Sheet and brand

Year grid

Twelve months for every member on one screen: each month is a strip of one-day slivers, so a year's leave reads as colour blocks.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

The year grid answers "who is away when this year?" for the whole team. Each cell is a link to that month in the team grid, and inside it one sliver (.sliver) stands for each calendar day, coloured by the same status tokens as the sheet cell. Weekends are the soft red (off-soft) so they separate days without dominating.

The year page pairs the grid with a summary table (.summary-table) giving each person's allowance, used, requested and left days, with a .usage-bar of confirmed (green) and requested (yellow) segments. Use the year grid for overview and the team grid for editing; slivers are links, never paint targets.

Anatomy

  1. Month header.year-grid__month: a link ("Jul") to that month in the team grid, caption-size semibold.
  2. Name cell.year-grid__name with avatar and name, role="rowheader".
  3. Month cell.year-month: a link wrapping up to 31 slivers, 1.75rem tall. Its aria-label summarises the month.
  4. Sliver.sliver[data-status]: one calendar day. Weekends use off-soft; working days empty.

Sliver states

A sliver can be any status; the four on the sheet plus empty. In the year grid weekends are written as data-status="off" and the CSS renders them with off-soft, so a confirmed week reads as colour with quiet gaps.

Sizes

Not applicable: the year grid has one density: 12 month columns of at least 3.9rem and rows 1.75rem tall; width, not size, adapts (it scrolls).

States

A month cell is a link, so its states are link states; the slivers inside it have no states of their own.

Responsive behaviour

  • The grid is minmax(7.5rem, 10rem) plus twelve minmax(3.9rem, 1fr) columns with min-width: 58.75rem. It always scrolls horizontally inside .grid-card; the first column is not sticky today (see drift).
  • Below 768px lead with the summary table (it reflows to its own scroll wrapper, .table-wrap) and let the grid scroll.
  • A sliver is about 0.13rem wide at the minimum month width; you read patterns, not days. Hovering or focusing a month cell exposes the exact count through its name.
  • Touch: the month cell is a 62px by 28px link (above the 24px minimum). A tap opens the month in the team grid; there is no hover dependency.

Theming

Slivers use --status-bg and the same status tokens as the cell; off and empty slivers use --color-status-off-soft and --color-status-empty, which are semi-transparent so the card surface shows through in both themes. The usage bar track is --color-bg-subtle-hover.

.year-grid { --space-2: var(--space-1); }   /* tighter year view: change the gap token locally */

Accessibility

Role and pattern

A grid of links: role="grid" labelled "Time off by month, 2026" with column headers for months (each a link) and row headers for members. Each .year-month is an <a href> with an aria-label that summarises the month; the slivers inside are decorative and have no role. The summary table is a native <table> with a visually hidden caption; each usage bar is role="img" with a sentence.

Keyboard

KeyAction
Tab / Shift+TabMoves through the month links in reading order (rows are not a roving grid because every cell is a link).
EnterOpens that member's month in the team grid.
SpaceNo effect on a link; use Enter.

Focus

The link draws the shared ring with outline-offset: 2px (.year-month:focus-visible), outside the sliver strip, so the ring sits on the card surface where it reads at 3:1.

Labelling

"Maya Chen, July: 5 confirmed days off". The name carries the count because the slivers cannot: at this size the glyphs are omitted, so colour is supported by the name and by the month header, not by a glyph. Month header links read "Jul"; give them aria-label="July 2026" when the year is not in the surrounding heading.

Motion

Nothing animates except the hover outline, which is instant under reduced motion.

Touch

Each month cell is a single link, 3.9rem by 1.75rem at least. Do not make individual slivers tappable: they are under 24px wide.

Content

  • Month headers are three-letter English months (Jan to Dec); full names appear in names and headings.
  • Month-cell names read ", : N confirmed days off"; zero is spelled "0 confirmed days off".
  • Summary columns: Allowance, Used, Requested, Left, in that order, as whole days. The table caption is "Allowance in 2026".
  • Do not label the year grid "calendar"; that word is the month sheet.

Drift fixed during extraction:

  • The first column (names) is not sticky in .year-grid, unlike .team-grid; on a phone the names scroll away with the months. Suggested: share the .grid-name sticky rule.
  • Slivers have no glyph, so on the year view colour carries the status and the month-cell name only counts confirmed days; requested and tentative days are not in the name.
  • At the minimum 3.9rem month width, 31 slivers are about 1px wide with 1px gaps, so individual days are barely resolvable below about 1400px wide; the grid is a pattern view.
  • The mocks' .sliver only maps off to off-soft, so the grid's weekend colour differs from the team grid's full red on purpose.
