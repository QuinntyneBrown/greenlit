Radio group

A radio group picks exactly one option from a short list that stays visible, and submits it with the form.

WCAG 2.2 AAStatus: stableSince v1.0
  • Overview

Overview

Use a radio group when the user must choose one of two to five options, each needs a label or explanation, and the choice is submitted with a form: for example whether a member is a Member or a Manager, or what happens to a request. Each option is a .choice row with a native radio input.

For a choice that takes effect immediately and is part of a toolbar, use a segmented control (which follows the same ARIA radiogroup model). For more than about five options use a select. For zero-to-many use checkboxes. Always provide a default so the form can never be submitted with nothing selected.

Anatomy

  1. LegendThe group's question or noun, in the label style. Names the group for assistive technology.
  2. Radio.choice input[type=radio]: 1.25rem circle; selected fills with --color-accent and shows a centre dot.
  3. LabelShort option name; the whole row is the target.
  4. DescriptionOptional small that says what the option does.

Variants

One look; radio groups differ only in what each option says.

Plain options.

Sizes

Not applicable: One size: a 1.25rem circle in a row at least 24px high. The row, not the circle, is the target.

States

Selected is the real checked property. Focus is forced with data-state; there is no hover style (see drift). Only the selected radio of a group is in the tab order.

Radio

Both themes

Role
Role
  • A group has no "none selected" state in the finished form; pre-select the safest default.
  • Invalid (aria-invalid="true" on the radios) tints the circles' border; report the problem once with a .field__error under the group.

Responsive behaviour

  • Options stack vertically at every width; the legend and the first option stay together (keep the fieldset out of page breaks).
  • Descriptions wrap under the option name and align to the label text, not the circle.
  • Do not lay radios in a row to save space. If two options fit on one line comfortably, a segmented control is the better choice.

Theming

Same tokens as the checkbox: --color-bg-surface, --color-border-strong, --color-accent, --color-fg-on-accent (the centre dot). The dot, not the fill alone, marks selection, so it still reads when colours are overridden.

.settings .choice input[type="radio"]:checked { background: var(--color-brand-strong); border-color: var(--color-brand-strong); }

Accessibility

Role and pattern

Native radios in a <fieldset> with a <legend>, following the APG Radio Group pattern. A group shares one name.

Keyboard

KeyAction
Tab / Shift+TabMoves into the group onto the selected radio (or the first, if none is selected) and out again.
→ / ↓Selects and focuses the next radio; wraps to the first.
← / ↑Selects and focuses the previous radio; wraps.
SpaceSelects the focused radio if it is not selected.

Focus

The shared ring is drawn around the focused circle. Because arrow keys select as they move, focus and selection always agree.

Labelling

The legend names the group; each option's label is its name; a description is linked with aria-describedby (or read as part of the label when it is inside it). Provide the legend even when it is visually quiet. Never use placeholder-style hidden legends for a required decision.

Contrast

Circle edge on page
Selected fill on page
Dot on selected fill
Label on page
Description on page

Motion

Fill and border change over --duration-fast; the dot appears instantly.

Touch

The whole row is the target and is at least 24px high; with a description it is taller. Spacing between rows is 4px of padding plus the stack gap.

Content

  • The legend is a short noun or question: "Role", "When someone leaves the team".
  • Options are parallel: all nouns, or all short verb phrases. Put the safest or most common first.
  • A description says what happens, in one sentence, without repeating the label.
  • Never include "None of the above" unless it is a real option.
