Tooltip

A tooltip is a short, non-interactive label that names or briefly explains an icon-only control on hover and focus.

WCAG 2.2 AAStatus: provisionalSince v1.0

Overview

.tooltip is a small dark bubble with an arrow, positioned above its trigger. It is shown through .has-tooltip on hover and keyboard focus. In Greenlit it describes icon buttons whose meaning is not universal (for example a lock icon or a refresh) and sheet cells' long date labels; the sheet's primary information is never only in a tooltip.

Use a tooltip only for a supplement to a control that already has an accessible name. Do not put essential information, links or buttons in one, and do not use it on touch where hover does not exist: for anything a person must read, use inline message or visible text. For a list of actions use a menu.

Anatomy

  1. Bubble.tooltip: inverse surface, inverse text, caption size, 4px by 8px padding, shadow 2, single line (white-space: nowrap).
  2. Arrow5px triangle drawn by ::after pointing at the trigger.
  3. TriggerAny focusable control inside .has-tooltip with aria-describedby pointing to the tooltip's id.

Variants

There is a single placement: above the trigger, centred, 8px away. Side and bottom placements are not defined.

Sizes

Not applicable: one size: caption text; the bubble grows with its single-line content.

States

The tooltip is hidden (opacity: 0, pointer-events: none) until the wrapper is hovered, contains focus, or is forced with data-state="hover".

  • The bubble uses --color-bg-inverse: dark in the light theme, light in the dark theme.

Responsive behaviour

  • Tooltips only exist where a pointer or keyboard focus does; do not rely on them on touch.
  • The bubble is nowrap and positioned 8px above the trigger, centred; near the left or right edge of a 360px screen it can overflow. Keep the text under about 30 characters or place the trigger away from the edge.
  • The bubble does not reposition; there is no flip logic in CSS, so use Angular CDK Overlay positioning for triggers near the viewport edge.
  • Never use a tooltip as the only place a mobile user can read a status.

Theming

Uses --color-bg-inverse, --color-fg-inverse and --shadow-2; the arrow shares the surface token. It is therefore light on dark pages and dark on light pages by design.

.tooltip { font: var(--text-body-sm); }  /* larger tips for low-vision audiences */

Accessibility

Role and pattern

WAI-ARIA APG Tooltip pattern: role="tooltip", the trigger refers to it with aria-describedby, and it appears on both hover and keyboard focus. WCAG 1.4.13 asks that content on hover or focus is dismissible (Esc), hoverable and persistent.

Keyboard

KeyAction
TabFocusing the trigger shows the tooltip; moving away hides it.
EscDismisses the tooltip without moving focus (requires script; the CSS-only version does not do this).

Focus

The trigger takes the shared ring; the tooltip is not focusable. It is revealed by :focus-within, so focus on the button shows it with no script.

Labelling

The tooltip supplements the accessible name; it does not replace it. An icon button must keep its own aria-label; aria-describedby adds the tooltip text as the description. Do not put the same text in both (it is read twice).

Contrast

Text on bubble
Bubble on canvas

Motion

Opacity fades over --duration-fast. There is no movement, so reduced motion needs no override.

Touch

Hover does not exist on touch. Do not hide meaning in a tooltip; give the trigger a visible label or put the text on the page. Long-press tooltips are not provided.

Content

  • Sentence fragment, no full stop: "Pick at least one day first".
  • Under about 40 characters, one line.
  • Never repeat the control's name; add something it does not say.
  • No links, buttons or formatting inside.
