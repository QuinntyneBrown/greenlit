Checkbox

A checkbox is an independent yes/no choice, or one of several choices where any number can be on.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

Use a checkbox for an option that is on or off and takes effect when the form is submitted, or to mark rows for a bulk action, as the "Select all pending requests" box on the Requests screen does. Several checkboxes in a group are independent; any combination is valid.

For a setting that applies the moment it is flipped (notifications, preferences) use a switch. For one choice out of several use a radio group. For choosing a status to paint use a segmented control. Do not use a checkbox to trigger an action; that is a button.

Anatomy

  1. Box.choice input[type=checkbox]: a 1.25rem square, --radius-xs, strong border; checked fills with --color-accent and draws a tick with clip-path.
  2. LabelThe text inside the wrapping <label class="choice">. The whole row is the click target.
  3. Description (optional).choice__text small: muted second line, for a consequence or example.

Sizes

Not applicable: One size: a 1.25rem box in a row at least 24px high (<code>--target-min</code>). The row, not the box, is the target.

States

Checked is the real checked property; the kit also supports :indeterminate for a "some selected" parent box, which can only be set from script, so it cannot be shown in this static page. Focus is forced with data-state; hover has no style of its own (see drift).

Checkbox

Both themes

  • Indeterminate shows a dash instead of a tick on a parent box when only some children are selected. Set input.indeterminate = true in script and expose it as aria-checked="mixed" automatically (native).
  • Invalid turns the box border red (aria-invalid="true"); always add a .field__error message, since the border is a small target.
  • Disabled dims the box, the label and the description; explain why in help text if it is not obvious.

Responsive behaviour

  • The label wraps; the box stays top-aligned with the first line (align-items: flex-start).
  • Rows are at least 24px high (--target-min) and the whole row is clickable, so they work on touch. Stack choices vertically; never lay them out in a row on a phone.
  • In dense lists (the Requests header) the row is compacted with min-height: auto because the surrounding row supplies the spacing.

Theming

Reads --color-bg-surface (box fill), --color-border-strong (edge), --color-accent (checked fill and border) and --color-fg-on-accent (the tick). In dark mode the accent inverts to near-white and the tick to near-black, which keeps the checked box above 3:1 against the page.

/* Brand-green checkboxes for the settings area */
.settings .choice input:checked { background: var(--color-brand-strong); border-color: var(--color-brand-strong); }

Accessibility

Role and pattern

Native <input type="checkbox"> following the APG Checkbox pattern. Groups use <fieldset> and <legend>. No ARIA is added to the native input; a tri-state parent is the native indeterminate property.

Keyboard

KeyAction
Tab / Shift+TabMoves between checkboxes; each is its own tab stop.
SpaceToggles the focused checkbox. (Enter submits the form.)

Focus

The shared ring, 2px in --color-focus-ring, drawn around the box. The label text does not draw its own ring: focus is on the input.

Labelling

The wrapping <label> gives the box its name and enlarges the target. A group has a legend. When the box has no visible text (a row selector) use aria-label="Select Ana Ruiz". A description is linked with aria-describedby. State is the checked property: never convey it by colour alone, the tick shape does.

Motion

Fill and border change over --duration-fast; the tick appears instantly. Instant under prefers-reduced-motion.

Touch

The 20px box sits in a full-width row at least 24px high, with 4px vertical padding: the practical target is the whole label. On touch lists add min-height: var(--target-comfortable) to the row.

Content

  • Label states the option affirmatively: "Email me when a request is decided", not "Don't send emails".
  • A bulk-select box says what it selects ("Select all pending requests").
  • Keep labels to one line; put detail in the description.
  • Never pre-check a box that opts the user into something they did not ask for.
