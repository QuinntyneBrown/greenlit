Skeleton

Skeletons hold the shape of content while it loads, so the page does not jump when the real thing arrives: text lines, a title, a circle and a rectangle.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

A skeleton is a placeholder block with a soft shimmer. Use it to reserve space for content that is loading and whose shape you know: the calendar grid, a member's name and avatar, the fields of a settings form. It is the default loading state for every page and region in Greenlit.

Do not use it for a wait on a single control (use a spinner or a busy button), for a task with measurable progress (progress bar), or for empty results (empty state). Skeletons stand in for content that will arrive; if it will not, show an empty or error state, not a skeleton forever.

Anatomy

  1. Circle.skeleton--circle: an avatar or a status dot placeholder; size it with inline width and height.
  2. Title.skeleton--title: 1.5em tall, 40% wide, for headings.
  3. Text lines.skeleton--text: 0.9em lines; the last line is 60% wide to suggest a paragraph end.
  4. Rectangle.skeleton--rect: a field, button or card block with the medium radius.

Variants

Four shapes. All are aria-hidden blocks; the container carries the busy state.

.skeleton--title and .skeleton--text. A run of text lines ends with a 60% line.

Sizes

Skeletons have no fixed sizes: each takes the size of the content it replaces. Use the spacing scale for fixed sizes (--space-6 for an avatar, --space-10 for a control, --space-24 for a name) and percentages for widths of text. Match the real element's dimensions closely, because the point is to avoid layout shift. min-height: 1em stops an unsized skeleton collapsing.

States

A skeleton is shown while loading, then replaced by content; it has no interactive states.

Both themes

  • Loading: shimmer sweeps across at 1.4s per cycle. The container is aria-busy="true".
  • Loaded: replace the skeleton in place with the same dimensions and remove aria-busy; no animation is needed.
  • Reduced motion: animation: none leaves a still, neutral block. Nothing else changes.
  • Error: if loading fails, replace the skeleton with an error empty state; never leave it shimmering.

Responsive behaviour

  • Skeletons mirror the layout they replace, so they reflow exactly as the real content does at each breakpoint (grid columns, stacked fields).
  • Percentage widths for text lines let them shrink on a phone; fixed sizes from the spacing scale keep avatars and controls the right size.
  • On the calendar, one skeleton cell stands for each day column; at 360px the grid scrolls horizontally exactly as it does when loaded.
  • Limit the number of skeleton rows to what fits one screen (about 6): more adds shimmer without information.

Theming

The shimmer is a gradient of --color-bg-subtle with a lighter band of --color-bg-subtle-hover, so it adapts to each theme and stays low contrast on purpose: a skeleton is a hint, not content. It sits on the card or page surface and is never given a border.

.skeleton { background: linear-gradient(90deg, var(--color-bg-subtle) 25%, var(--color-bg-subtle-hover) 37%, var(--color-bg-subtle) 63%); }

Accessibility

Role and pattern

Skeletons are decorative: mark each block aria-hidden="true" and put aria-busy="true" on the container that is loading (WAI-ARIA aria-busy). Provide one visually hidden role="status" line ("Loading the team calendar") so assistive technology announces the wait once. When content arrives, remove aria-busy and announce nothing further unless the loaded region is a live one.

Keyboard

KeyAction
TabSkips every skeleton. Do not render real controls (inputs, buttons) in a disabled loading state unless they are needed; leave them out.
EscNot handled.

Focus

No skeleton is focusable. When content replaces the skeleton, keep keyboard focus where it was; if focus was inside the loading region, move it to the region's heading after load so it is not lost.

Labelling

Blocks are silent. The hidden status line names what loads ("Loading the team calendar", "Loading your account") and nothing else. Do not give each block its own label: screen-reader users would hear a list of empty placeholders.

Motion

The shimmer sweeps the background position for 1.4s, looping, with --ease-standard. Under prefers-reduced-motion: reduce the animation is removed and the block stays a flat --color-bg-subtle rectangle. A looping decorative animation lasting beyond five seconds must be pausable under WCAG 2.2.2: loading states should resolve or fail inside that window, so surface an error rather than shimmering on.

Touch

Skeletons are not targets and take no input. Do not make a skeleton clickable; if the real element is tappable, it becomes so only when it replaces the skeleton.

Content

  • A skeleton has no copy. The only words are the hidden status line, which names the region: "Loading the team calendar".
  • Show skeletons only for waits over about 300ms; show nothing for faster loads.
  • Match the number of lines and the proportions of the real content so the swap does not shift the page.
  • When loading fails, replace the skeleton with a message in the product's voice ("We couldn’t load the calendar"), not an empty box.
