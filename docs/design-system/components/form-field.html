Form field

A form field wraps one control with its label, optional marker, help text, error message and counter, and wires them together for assistive technology.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

Every input in Greenlit sits in a form field (.field): a vertical stack of the label, the control, then help text, an error or a counter. It is the unit the user reads, the unit that carries the error, and the unit you place in form layout.

The field does not style the control itself; it holds a text field, textarea or select. Choice controls (checkbox, radio group, switch) carry their own labels and groups use a fieldset instead.

Anatomy

  1. Label.field__label: the field's visible name, bound with for.
  2. Optional marker.optional in --color-fg-subtle: required is the default, so only optional fields say so.
  3. ControlAny single-line control with matching id and aria-describedby.
  4. Message.field__help (muted) or .field__error (danger colour, leading warning glyph, linked by id).

Sizes

A field has no size of its own: it is as wide as its container and as tall as its parts. The control inside takes .input--sm or .input--lg; gap between parts is --space-1 (4px).

States

The field shows what its control shows plus the message slot. Error state is two parts that must travel together: the control's aria-invalid="true" and a .field__error referenced by aria-describedby.

  • Show an error after the user leaves the field or presses submit, never while they type the first character.
  • Move the error text, not the control: the message appears below the control and pushes content down. Reserve no space for it.
  • For a failed form, also show a form summary at the top that links to each field.

Responsive behaviour

  • Labels sit above the control at every width; there is no side-by-side label layout.
  • Help and error wrap within the field's width; they never truncate. Keep each to about two lines at 360px.
  • The field fills its grid cell (minmax(0, 1fr) columns) so a long unbroken value cannot widen the page.

Theming

Label colour --color-fg-default, help --color-fg-muted, optional marker and counter --color-fg-subtle, error --color-danger-fg. The warning glyph inherits the error colour. Messages are text, so they use the foreground danger token (which passes 4.5:1 on the page in both themes), not the solid one used for borders.

.field__help { font: var(--text-caption); }   /* a quieter help line */

Accessibility

Role and pattern

HTML form labelling, not an ARIA widget: <label for> binds the label, aria-describedby lists the ids of help and error text (space-separated), aria-invalid="true" marks an error. Inline errors need no role="alert" when a form summary announces them; if a field is validated on its own, add aria-live="polite" to the message.

Keyboard

KeyAction
TabMoves from field to field in DOM order, which must match the visual order.
EnterSubmits the form from any single-line control.
Click labelFocuses the control (and toggles it for checkbox rows).

Focus

On submit with errors, move focus to the first invalid control, or to the summary. Do not move focus while the user is typing. The summary links jump to the field with the matching id.

Labelling

Every control has exactly one visible label. A control that is labelled in context (a number input in a row) uses aria-label containing the visible text. Help and error ids follow the pattern {fieldid}-help and {fieldid}-err so they are predictable. The error text names the field and the fix ("Enter a valid email address, like name@company.com.").

Motion

Errors appear without animation so they are announced and read immediately; nothing slides.

Touch

The label is a tap target for the control. Keep 16px (--space-4) between fields so a mis-tap does not hit the neighbour.

Content

  • Labels are nouns in sentence case; the error is a full sentence with a full stop that states the fix: "Give your team a name.", "Enter a valid email address, like name@company.com."
  • Do not blame: "Enter a number other than 0", not "Invalid input".
  • Help is one sentence and says why or how. Don't repeat the label.
  • Optional is marked in the label; required is not marked.
