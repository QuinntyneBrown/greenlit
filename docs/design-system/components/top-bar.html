Top bar

The top bar is the app's single global header: logo, the four destinations, the team name and the account menu.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

The top bar (.topbar.topbar--app) is rendered on every signed-in screen and holds three things: the logo lockup as the way home, the app navigation, and the end cluster with the team name and the account menu. It is sticky to the top of the viewport and has a hairline bottom border, not a shadow, so the sheet underneath keeps the focus.

Use it once per page. Auth and full-page message screens (sign in, offline, not found) use the bare shell without a top bar: there is nowhere to navigate to. Page-level controls such as the month arrows belong in period navigation in the page body, not in the bar.

Anatomy

  1. Logo lockupLinks to the calendar. aria-label reads "Greenlit, team calendar"; the wordmark is aria-hidden.
  2. App navigationThe main <nav>, with the current page marked by aria-current and a brand underline.
  3. Team name.topbar__team, muted text; hidden below 640px to save width.
  4. Account menu.user-menu with an .avatar-btn that opens the account menu.

Variants

The top bar has one construction. What changes from screen to screen is the current destination and whether the account menu is open.

Sizes

Not applicable: the bar has one height, <code>--layout-topbar-height</code> (56px); only its horizontal padding changes with the breakpoint.

States

The bar itself has no interactive states. Its parts do: links and the avatar button show hover and the shared focus ring; the avatar button is also an expanded state while the menu is open.

  • Sticky. position: sticky; top: 0 at --z-sticky; it is below dialogs, drawers and toasts. In these examples sticky is overridden so the bar does not follow you down the page.
  • Inert behind a dialog. When a dialog opens the whole page, bar included, is made inert and hidden from assistive technology.

Responsive behaviour

  • Below 768px the app navigation wraps to its own full-width row under the logo and account menu (order: 3; width: 100%) and scrolls horizontally if it ever overflows; the bar grows from one row to two.
  • From 768px (--layout-breakpoint-md) the navigation sits inline between the logo and the end cluster, with a 32px column gap, and each link is the full bar height.
  • The team name (.topbar__team) is hidden below 640px and shown from 640px; the account menu still shows who is signed in through its accessible name.
  • The inner row uses .shell, so content aligns with the page below: 16px gutters on phones, 24px from 768px, capped at --layout-container-max.
  • Print hides the bar (@media print).

Theming

The bar reads --color-bg-surface and --color-border-default, and the link colours from the navigation. The brand underline and the green squares of the mark use --color-brand, which is a decorative colour and never carries meaning alone. Nothing in the bar needs a dark-specific rule.

/* Re-skin the bar surface for a partner theme */
[data-theme="partner"] .topbar { background: var(--color-bg-canvas); }

Accessibility

Role and pattern

A <header> (banner landmark) containing a single <nav aria-label="Main">. The account menu button follows the WAI-ARIA APG Menu Button pattern (aria-haspopup="menu", aria-expanded). The navigation is a set of links, not a menubar.

Keyboard

KeyAction
TabMoves through: skip link, logo, each navigation link, account menu button.
Enter / Space on the avatar buttonOpens the account menu and moves focus to its first item.
Arrow Up / Arrow Down in the menuMoves between menu items; Esc closes the menu and returns focus to the button.

Focus

Every link and the avatar button take the shared focus ring on :focus-visible. The first stop on every page is the skip link, which jumps over the bar to #main.

Labelling

The logo link has aria-label="Greenlit, team calendar" because its visible wordmark is decorative. The avatar button's name includes the person ("Account menu for Maya Chen") so it is not read as just "menu". The pending count is spelled out for screen readers ("4 pending").

Motion

Link colour transitions are the only motion, and none of the bar's own properties animate. Under prefers-reduced-motion the menu opens without scale.

Touch

Links are at least --target-comfortable (44px) tall on phones and the full bar height from 768px. The avatar button is 40px with padding; its row has 12px gaps.

Content

  • The team name is the only text in the end cluster: "Design team", not "Team: Design team".
  • Destination names are single nouns in sentence case, in the order Calendar, Year, Requests, Settings. Settings is shown to everyone; members see read-only sections.
  • Do not add a fifth destination without a requirement. The sheet is the product.
