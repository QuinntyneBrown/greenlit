Component · Data display

Table

Tables compare the same facts across people: allowance, days used, days left. Sticky header, numeric columns, optional sort and row actions, loading and empty versions.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

Use a table when readers scan down a column to compare values for several members: the year page's allowance summary is the model. Each row is one member; each column is one fact about them. A table is a real <table> with a caption and column headers, so assistive technology can announce "Left, column 5" while a reader moves across cells.

The month sheet is not a table component: it is the team grid, which uses its own cells and keyboard model. A list of things that each need a few lines and actions (requests, members) is a list or a request row, which reflow on a phone where a table can only scroll.

Anatomy

  1. Wrap.table-wrap clips the radius, draws the border and scrolls horizontally when the table is wider than its container.
  2. Column header<th scope="col"> on a sunken background, label type, sticky. .num right-aligns numeric columns.
  3. Name cellThe member: avatar plus name, a link when it opens the person page.
  4. Row actions.row-actions: icon buttons revealed on hover or focus. A summary table instead ends with a .usage-bar whose role="img" label carries the numbers.

Variants

One table, with a handful of cell conventions. The class on the table is .table; .summary-table only switches off wrapping and sizes the usage column.

  • Selected (aria-selected="true" on the row) tints the row with --color-accent-subtle; use it only in tables that really have selection, not to highlight "this is you".
  • Focus shows on the controls inside cells (links, buttons), never on the row itself.

Responsive behaviour

  • The table is never reflowed into cards: .table-wrap scrolls horizontally (overflow-x: auto) and the page itself never does. At 360px the usage column (min 9rem) is the one that scrolls away first.
  • The header is position: sticky inside the wrap; give the wrap a max-height when the table is long.
  • .summary-table sets white-space: nowrap so names and numbers never wrap awkwardly.
  • @media (hover: none) shows row actions permanently, since touch has no hover.
  • For a phone-first list of requests or members, use request row or member list, which reflow.

Theming

The table reads surface tokens only: --color-bg-surface for cells, --color-bg-surface-sunken for the header, --color-border-default for rules, --color-bg-subtle and --color-accent-subtle for hover and selection. Usage-bar segments take their colour from the sheet's status tokens through --status-bg, so confirmed and requested look the same here as on the sheet in either theme.

/* Denser table for a settings screen, no new component */
.table--dense th, .table--dense td { padding-block: var(--space-2); }

Accessibility

Role and pattern

Native <table> semantics, not the ARIA grid pattern: the table is read-only and its interactive parts are ordinary links and buttons. Sortable columns follow the APG sortable table example: a button inside the column header with aria-sort on the <th>.

Keyboard

KeyAction
Tab / Shift+TabMoves through the links and buttons in cells in reading order. The table itself is not a tab stop.
Enter, Space on a sort headerSorts by the column, cycling ascending, descending. Focus stays on the header button.
Enter on a name linkOpens the member's page.
Screen-reader table commandsMove by cell and row with the header announced, because of scope="col".

Focus

Links and buttons inside cells show the shared focus ring. Row actions that are hidden at rest become visible as soon as focus enters the row (:focus-within), so a keyboard user never tabs onto an invisible control.

Labelling

Every table has a <caption> (visually hidden when the page heading already says it) and every header cell is <th scope="col">. An icon-only column gets a visually hidden header ("Actions", "Usage"). Usage bars are role="img" with a label such as "17 of 28 days taken, 5 requested", and the numbers also sit in their own columns, so colour is never the only carrier. Icon buttons in rows name the member: "Remove Ana Ruiz".

Contrast

Cell text on surface
Header label on sunken header

Motion

Row actions fade in over --duration-fast. Under prefers-reduced-motion the duration tokens collapse and they simply appear. Skeletons stop shimmering.

Touch

Row action buttons are small (32px) and 8px apart; on touch they are always visible, never behind a hover. A name link spans the full text height. Where a row needs larger targets, use a list.

Content

  • Column labels are nouns in sentence case: "Allowance", "Used", "Left". Units go in the label or caption, not in every cell.
  • Right-align numbers (.num) and use whole days: "11", not "11.0 days".
  • Name the table in the caption with the period: "Allowance in 2026".
  • A real zero is "0"; an unknown value is an en dash.
  • Sort order is stated in text near the table ("Sorted by days left"), not only by the header arrow.
