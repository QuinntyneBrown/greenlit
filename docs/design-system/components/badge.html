Badge and status

Small labels that say where something stands: tone badges, the pending-request count pill, request status with its dot, and the inline save status.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

These four small components share one job: state a status in a few words, next to the thing it describes. Use a badge for a short standalone label (Draft, Needs review), a count pill for the number of pending requests beside "Requests" in the navigation, a request status (.req-status) in a request row, and an inline status for the result of the last save next to a form's button.

They are not for day status. Tentative, requested and confirmed days are shown on the sheet by sheet cells and named by the legend; the yellow dot of a pending request is a hint, and the word "Pending" is what says it. For toasts and banners that interrupt, see toast and alert; for filters and toggles that the user can press, see chip.

Anatomy

  1. DotA 6px (badge) or 8px (request status) disc drawn with ::before in the text colour or the status colour. Decorative; the word is the state.
  2. LabelOne to three words. Overline type uppercase in a badge, caption type in a request status.
  3. ContainerPill (--radius-full) with a tone background in a badge; no container in a request status or inline status.

  • No hover, focus or active state: none of these are interactive. The count pill sits inside a link, which has the states.
  • In forced-colors mode .badge gets a system-colour border so the pill shape survives without its tint.

Responsive behaviour

  • All four are white-space: nowrap and never shrink below their text. The containing row wraps or truncates; a badge never does.
  • In a request row, the status sits in the actions column. Under 48rem the row stacks, and the status moves under the note, left-aligned; from 48rem up it is right-aligned (.request-row__actions { justify-content: flex-end }).
  • The count pill stays on the "Requests" link in the scrolling mobile navigation, so it scrolls with the link.
  • Inline status text wraps under the button on narrow forms; keep the message short so it fits on one line at 360px.

Theming

Tone badges read the semantic feedback tokens (--color-info-bg/fg and so on) which have separate light and dark values, so the pair keeps its contrast in both themes. Request status dots read the sheet status tokens through the component token --dot; the count pill uses the requested colour with --color-on-status text.

/* Add a "Holiday" badge in the off colour without a new class */
.badge[data-kind="holiday"] { background: var(--color-status-off-soft); color: var(--color-fg-default); }

Accessibility

Role and pattern

Plain inline text, not a widget. Status that changes after an action is announced through an existing live region; .inline-status goes inside role="status" (or aria-live="polite"), set before the text changes. There is no APG pattern: this follows the names and descriptions guidance by putting the state in text.

Keyboard

KeyAction
TabDoes not stop on any of these. Inside a link (count pill) the link is the tab stop.

Focus

None of its own. Hide nothing that holds focus: the count pill is inside the navigation link, so the link's ring surrounds it.

Labelling

Status is in words, never in the dot or tint alone (WCAG 1.4.1): "Pending", "Approved", "Declined". A bare number needs a hidden unit ("4 pending"). Icons in inline status are aria-hidden; the message is the content. When a badge sits in a table cell or list row, its text is part of the row's reading order.

Motion

None. A count that changes updates in place without animation.

Touch

Not targets. A count pill inside a navigation link inherits the link's 44px height.

Content

  • One to three words, sentence case in the source (the badge uppercases for display): "Needs review", not "NEEDS REVIEW".
  • Name the state, not the colour: "Pending", never "Yellow".
  • Counts show the number only; a hidden unit follows (" pending"). Cap at 99+, and hide the pill at zero.
  • Inline status says what happened in the past tense: "Password updated", "Could not save". Add "Retry" as a button, not in the status.
  • Use the product's vocabulary: Pending, Approved, Declined for requests; Tentative, Requested, Confirmed for days.
