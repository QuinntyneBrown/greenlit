Component · Navigation

Period navigation

Period navigation is the pair of arrows beside the month or year title that steps the sheet one period at a time.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

.period-nav groups two ghost icon buttons (.period-nav__arrows) and the page's <h1> title: "November 2026" on the calendar, "2026" on the year view. It sits in .page-title-row at the left, with page controls such as the paint picker on the right.

Use it for stepping through time, one month or year per press. It is not for jumping: choose a month from the year view, whose month headers are links. It is not pagination; the sheet is never paged. In these examples the title is shown as a styled heading; the real page uses the single <h1>.

Anatomy

  1. PreviousGhost icon button, aria-label="Previous month".
  2. NextGhost icon button, aria-label="Next month".
  3. Period titleThe page title, in the h1 style; this is what the arrows change. Names the period in words.

The unit changes: the arrow labels name it.

Sizes

Not applicable: the arrows are the 40px medium icon button and the title is the page h1.

  • Loading: the title updates immediately and the sheet shows skeleton cells while the other month loads.
  • Limits: there are none today; a team can browse any month. If a limit is added, use disabled plus a tooltip that says why.

Responsive behaviour

  • Arrows and title stay on one line when they fit; the group has flex-wrap: wrap, so the title drops under the arrows at extreme widths (below about 320px).
  • In .page-title-row the period navigation is the first child; page controls wrap beneath it below 640px.
  • The title is the h1; it uses the h1 type scale at every width, so "September 2026" fits 360px.
  • Arrows stay 40px square at every width; they never collapse into a menu.

Theming

Everything comes from the button (ghost variant) and the heading tokens. No component-level tokens of its own.

.period-nav { gap: var(--space-2); }  /* tighter title spacing */

Accessibility

Role and pattern

Two native buttons and a heading; no composite widget. This is the common "previous / next" button pair, not a toolbar, so there is no arrow-key handling. After a press, announce the new period (a polite live region with "November 2026") or move the focus-visible title, because the sheet content changes.

Keyboard

KeyAction
TabPrevious, then next, then the page controls.
Enter / SpaceSteps one period; focus stays on the pressed button so repeated presses are quick.

Focus

Each button shows the shared ring. Keep focus on the button after the sheet re-renders; never reset it to the document start.

Labelling

Icon-only buttons have aria-labels that name the unit ("Previous month", "Next year"). The title is the h1, so the page's accessible name changes with the period.

Contrast

Title on canvas
Icon on ghost button
Hover fill on icon
Focus ring on canvas

Motion

Button colour transitions only. Do not animate the sheet sliding between months; the change should be immediate and predictable.

Touch

40px square buttons with no gap between the pair; add 4px margin if mis-taps are reported. The group sits near the left edge, away from the sheet's scroll area.

Content

  • The title names the period in words: "November 2026", not "11/2026".
  • Arrow labels name the unit: "Previous month".
  • No "Today" label is needed; the sheet marks the current date itself.
