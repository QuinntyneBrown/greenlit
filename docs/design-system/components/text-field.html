Component · Inputs

Text field

A text field takes a single line of text, an e-mail address, a password, a number or a search term. It always lives in a form field with a visible label.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

Use a text field (.input) for short free-form input: team name, member name, e-mail, password, days per year, a holiday's date. One line, one value. For several lines use a textarea; to choose from known options use a select, a radio group or a segmented control; for a small adjustable number with plus and minus use a counter.

The date input type (type="date", value yyyy-MM-dd) and a placeholder example ("e.g. Family trip") follow the same rules. The input is not labelled by its placeholder: put it in a form field (label, help, error) and arrange fields with form layout. The kit also provides a search variant with a leading icon, an input group with a text add-on, and the number and password input types.

Anatomy

  1. Label.field__label, bound with for. Always visible; never replaced by a placeholder.
  2. Input.input: 40px high, 1px --color-border-strong border, --radius-md, surface background.
  3. Help text.field__help linked with aria-describedby.

Variants

The input types change the keyboard and validation, not the styling. Always set type, autocomplete and name.

Text, e-mail, password and number inputs. Narrow numeric fields use tabular numerals (.days-input .input).
HTML
<div class="stack" style="width: 100%; max-width: 22rem;"><div class="field"><label class="field__label" for="tf-v-email">Email</label><input class="input" type="email" id="tf-v-email" name="tf-v-email" placeholder="name@company.com" autocomplete="username"></div><div class="field"><label class="field__label" for="tf-v-pw">Password</label><input class="input" type="password" id="tf-v-pw" name="tf-v-pw" autocomplete="current-password"></div><div class="field"><label class="field__label" for="tf-v-days">Days per year</label><input class="input" type="number" id="tf-v-days" name="tf-v-days" value="25" min="0" step="0.5"></div></div>

Search

.search wraps an icon and an .input; the icon is decorative and inset 12px, the input adds left padding for it. Without a visible label the field is named with aria-label.
HTML
<div class="search" style="width: 100%; max-width: 22rem;"><svg class="icon" aria-hidden="true" viewBox="0 0 24 24"><circle cx="11" cy="11" r="6.5"/><path d="m16 16 4.5 4.5"/></svg><input class="input" type="search" id="tf-v-search" name="tf-v-search" aria-label="Search members" placeholder="Search members"></div>

Input group (add-on)

days / year
.input-group fuses an input with an .addon that states the unit. The label names the field; the add-on is a text hint.
HTML
<div class="field" style="width: 100%; max-width: 22rem;"><label class="field__label" for="tf-v-grp">Allowance</label><div class="input-group"><input class="input" type="number" id="tf-v-grp" name="tf-v-grp" min="0" value="25"><span class="addon">days / year</span></div></div>

Sizes

Medium is the default (--control-height-md, 40px). Small (.input--sm, 32px) is for inline editing in rows such as the member list; large (.input--lg, 48px) is for auth screens where the field is the main task.

Heights --control-height-sm/md/lg; font --font-size-sm/md/lg.
HTML
<div class="stack" style="width: 100%; max-width: 22rem;"><input class="input input--sm" type="text" aria-label="Small, 32px" value="Small · 32px"><input class="input" type="text" aria-label="Medium, 40px" value="Medium · 40px"><input class="input input--lg" type="text" aria-label="Large, 48px" value="Large · 48px"></div>

States

Hover and focus are forced with data-state for review; real pages use :hover and :focus-visible. Invalid uses the real aria-invalid="true", disabled the native disabled attribute and read-only the native readonly attribute.

Both themes

  • Invalid is shown by a stronger border plus an inset line and by the .field__error message below it (which starts with a warning glyph). Colour is never the only cue. See form field.
  • Disabled fields leave the tab order. Prefer read-only when the value is still useful to read, copy or submit; for a fully locked form use fieldset disabled.
  • Read-only uses the sunken surface and stays focusable and selectable.
  • Loading: a field has no spinner. While a form submits, the submit button shows loading and fields stay as they are.

Responsive behaviour

  • Fields are width: 100% of their container; the layout (form layout) decides the columns. Do not set fixed widths except for short numeric fields (.days-input .input is 5rem).
  • At 360px a field and its label stack one per row; two-column grids collapse below 40rem.
  • Body text is 16px (--text-body) so iOS Safari does not zoom on focus. .input--sm lowers the size, so keep small inputs out of phone-first forms.
  • Use the right type and inputmode so phones show the e-mail, numeric or search keyboard.

Theming

Fields read --color-bg-surface (fill), --color-border-strong (edge), --color-fg-default (text), --color-fg-subtle (placeholder), --color-focus-ring (focus) and --color-danger-solid (invalid). The strong border token, not the default one, keeps the field edge above 3:1 on the page (WCAG 1.4.11); do not swap it for --color-border-default.

/* A compact filter bar on the Requests screen */
.filter-bar .input { min-height: var(--control-height-sm); font-size: var(--font-size-sm); }

Accessibility

Role and pattern

Native <input>; there is no ARIA role to add. The pattern is the HTML one: a visible <label for> plus aria-describedby for help and error text. A search field uses type="search" inside a role="search" form or landmark.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the field. Disabled fields are skipped.
Typing, ← →, Home, EndNative text editing.
EnterSubmits the surrounding form (single-line field).
↑ / ↓ (number)Steps the value by the step attribute.
Esc (search)Clears the field in browsers that support it.

Focus

Fields draw the same ring as every control, but inside the border: --focus-ring-width solid --color-focus-ring with zero offset, plus a border in the ring colour, so the focused edge is at least 3:1 against both the field and the page. The ring is shown for :focus-visible, which for text fields is every focus, pointer included.

Labelling

Every field has a visible <label for>. Placeholders are examples ("e.g. Company offsite"), not labels, and vanish when typing. Help and error are linked through aria-describedby, and the invalid field sets aria-invalid="true". Mark optional fields with "(optional)" in the label rather than required ones with an asterisk: most fields are required. Set autocomplete tokens (username, current-password, new-password, email) to satisfy WCAG 1.3.5.

Motion

Border colour and the invalid inset line transition over --duration-fast. They become instant under prefers-reduced-motion.

Touch

40px medium and 48px large fields exceed the 24px minimum; the label sits above the field and is tappable too (it focuses the input). Use .input--sm only inside rows separated by at least 8px.

Content

  • Label with a noun in sentence case: "Team name", "Email", "Days per year". Not "Enter your team name".
  • Placeholders show an example format ("name@company.com", "e.g. Company offsite"); never repeat the label, never carry the only instruction.
  • Help text explains why or how once, in one sentence ("Weekends and holidays are worked out in this time zone.").
  • Add-ons carry the unit ("days / year"); the label carries the meaning.
  • Keep sensible defaults (the manager's own name on Create team); do not pre-fill sample data.
