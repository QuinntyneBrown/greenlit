Drawer

The drawer is a side panel that opens a record in context; in Greenlit it shows one time-off request with its decision actions.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

.drawer is a modal panel fixed to the right edge (or the left with --left), 28rem wide, or 40rem with --wide, with a header, a scrolling body and an optional footer. In Greenlit it is the request detail: who asked, which days, the status, the note and the team those weeks, with Decline and Approve for the manager.

Use a drawer to read or act on one record while keeping the list visible behind it. Use a dialog for a short decision or form. Do not use a drawer for navigation or for a task that needs the whole screen: navigate to a page. Like a dialog it is modal: focus is trapped, the page behind is inert, and Esc closes it.

Anatomy

  1. Person and summary.drawer__person with an avatar, the member's name as the title (an h2 in the page) and a description of the days; the dialog's name and description.
  2. Close buttonGhost icon button, aria-label="Close".
  3. Body.drawer__body scrolls: status, sent date, days left, the note as a .quote.
  4. Footer.drawer__footer: Decline (secondary) then Approve (approve button); omitted once decided.

Sizes

Two widths, both capped at 100% of the viewport:

Standard · 28rem · .drawer
Wide · 40rem · .drawer--wide
Widths are set with width: min(100%, …) so the drawer becomes full width on phones.
HTML
<div class="stack stack--sm" style="width: 100%;"><div class="well" style="width: min(100%, 28rem);">Standard · 28rem · <code>.drawer</code></div><div class="well" style="width: min(100%, 40rem);">Wide · 40rem · <code>.drawer--wide</code></div></div>

States

See Variants for approved, busy and failed. The panel's own lifecycle:

  • Open: slides in from its edge over --duration-slow; the backdrop fades in; focus moves to the panel title or the first control.
  • Scrolling: the body scrolls (overflow: auto); header and footer stay in place.
  • Closed: Esc, Close or a backdrop click; focus returns to the request row that opened it.

Responsive behaviour

  • The drawer is width: min(100%, 28rem) (or 40rem wide), so below the width it fills the screen and behaves like a full-screen sheet; the backdrop is then hidden behind it.
  • From 640px the backdrop remains visible at the left (wide: from about 1000px).
  • The header keeps the avatar, title and Close on one row; the description truncates before it pushes Close out.
  • Body padding is 24px at every width; the footer buttons stay on one row and Approve stays rightmost.
  • The panel is full viewport height (top: 0; bottom: 0) and uses the dynamic viewport so the footer clears mobile browser chrome.

Theming

Surface --color-bg-surface-raised, shadow 4, hairline rules --color-border-default, backdrop --color-bg-backdrop. Same semantics as the dialog, so both themes behave identically.

.drawer--wide { width: min(100%, 48rem); }  /* a wider panel for a future split view */

Accessibility

Role and pattern

WAI-ARIA APG Dialog (Modal) pattern: the markup is <aside role="dialog" aria-modal="true"> with aria-labelledby the member's name and aria-describedby the day range. Build with Angular CDK Overlay/Dialog (project rule): trap focus, make the page inert, restore focus.

Keyboard

KeyAction
Tab / Shift+TabCycles within the drawer; the list behind is inert.
EscCloses the drawer and returns focus to the invoking request row.
Enter / SpaceActivates Close, Decline or Approve.

Focus

Focus lands on the title region or the first action on open (not on Approve), stays inside, and returns to the opening row on close. The shared ring is visible on the raised surface and inside the scrolling body.

Labelling

The title is the person, the description is the range and length ("16–20 Nov · 5 days"). Close is "Close". The status reads in words ("Pending") beside a coloured dot, so colour is not the only carrier. A failed decision is a role="alert".

Contrast

Text on raised surface
Description on raised surface
Approve label
Body text on quote
Focus ring on raised surface

Motion

Slides in over --duration-slow with --ease-enter; reduced motion shows it immediately.

Touch

Full width on phones; all controls are 40px. The close button is at the top right, reachable with a thumb on large phones if the sheet is full height; a bottom Close is not provided as Decline/Approve own the footer.

Content

  • Title: the member's name. Description: dates and length, "16–20 Nov · 5 days".
  • Footer buttons: "Decline" and "Approve", never "No" / "Yes". A decline opens a dialog for the optional reason.
  • After a decision remove the footer and show the outcome as status text, not as a disabled button pair.
  • Quote the member's note in curly quotes, verbatim.
