Dialog

The dialog is the modal for confirmations and short forms: sign out, remove a member, add a day off, decline a request.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

.dialog is a full-screen grid that centres a .dialog__panel over a .backdrop. It interrupts the current task, takes focus, makes the page behind inert, and ends with a decision. It always has a title, a description, a close button and a footer with one primary action and a way out.

Use it for: a confirmation that needs a decision (sign out, remove, decline); a short form that edits one thing (invite a member, adjust allowance, add a day off, new request). Per the project rules, button-triggered editing opens a dialog; there are no inline forms in pages. For reading a record with context use a drawer. For feedback after the fact use a toast. For a hint use a tooltip.

Anatomy

  1. Icon (optional).dialog__icon--danger or --info, 40px circle with a tinted background; decorative (aria-hidden).
  2. Title and description.dialog__title (h3 scale, an h2 in the page) labels the dialog; the description names the subject and is its aria-describedby.
  3. Close buttonGhost icon button, aria-label="Close". Same effect as Esc.
  4. Body.dialog__body.stack: the consequences or the form fields.
  5. Footer.dialog__footer, sticky; safe action first, primary or danger last.
  6. Backdrop.backdrop, --color-bg-backdrop, dims and blocks the page.

Variants

Documentation stages contain the fixed-position dialog in a clipped box; on a real page the dialog fills the viewport.

States

The dialog itself has one open state; what varies is the content state. Use the labelled examples in Variants for default, destructive, form, busy and failed. Invalid is a form dialog with field errors and a form summary (see the invalid mocks); over-allowance adds a warning alert.

  • Opening: panel slides up (phones) or scales in (--duration-slow); the backdrop fades in.
  • Closing: Esc, the close button, Cancel and a backdrop click all dismiss. While busy, dismissal is blocked.
  • Behind: the page, including the top bar and skip link, gets inert and aria-hidden.

Responsive behaviour

  • Below 640px the dialog is a bottom sheet: place-items: end center, no padding, top corners --radius-xl, full width, slides up.
  • From 640px (--layout-breakpoint-sm) it is centred with 24px padding, all corners --radius-lg, max-width 32rem (24rem small, 48rem large), scales in.
  • max-height: calc(100dvh - 48px): tall content scrolls inside the panel; header scrolls with it, the footer stays sticky; bottom: 0.
  • Footer buttons wrap (flex-wrap: wrap) and stay right-aligned; the primary remains last.
  • On a phone with the on-screen keyboard open the visible viewport shrinks; dvh units keep the panel fully visible.

Theming

The panel uses --color-bg-surface-raised and shadow 4; the scrim is --color-bg-backdrop. In dark the panel is lighter than the page so it stays distinct. Icon tints use the danger and info background and icon tokens.

.dialog__panel { border: 1px solid var(--color-border-default); }  /* defined edge on dark themes */

Accessibility

Role and pattern

WAI-ARIA APG Dialog (Modal) pattern: role="dialog", aria-modal="true", aria-labelledby the title, aria-describedby the description. Use role="alertdialog" only for a dialog that requires an immediate response and cannot be dismissed neutrally; Greenlit's destructive dialogs offer Cancel, so they stay dialog. Implement with Angular CDK Dialog (project rule), never a hand-rolled modal.

Keyboard

KeyAction
Tab / Shift+TabCycles through the dialog's controls only (focus trap); the page behind is inert.
EscCloses the dialog (not while busy) and returns focus to the control that opened it.
EnterIn a form, submits; on a button, activates it. In a destructive dialog Enter must not default to the danger button when focus is on a field.

Focus

On open, focus goes to the first field in a form dialog (autofocus) and to the safe action (Cancel) in a destructive one, never to the danger button. Focus returns to the invoking control on close. The ring uses the shared token and is visible on the raised surface.

Labelling

The title is the name; the description is the description. The close button is labelled "Close" (not "x"). A failed state uses role="alert" so it is announced without moving focus. The busy button keeps its name and adds aria-busy; announce completion through a toast or by closing.

Motion

Slide-up on phones and scale-in on desktop over --duration-slow, backdrop fade over --duration-base. Under prefers-reduced-motion both collapse to an instant appearance; no information depends on the motion.

Touch

Buttons are 40px; the close button is 40px at the top right, away from the primary action. On phones the sheet leaves the top of the page visible so the person knows where they are. Backdrop tap dismisses unless busy.

Content

  • Title is a question for a decision ("Remove Ben from the team?") or a verb phrase for a form ("Add a day off").
  • Description states the subject and the consequence in one sentence; a destructive body lists what stays and what goes.
  • Buttons: the safe action first ("Cancel", "Stay signed in"), the confirm last and named for the outcome ("Yes, remove Ben", "Sign out").
  • Busy label is the progressive verb: "Removing…". Failed copy says what failed and that nothing changed.
  • Sentence case, curly quotes and apostrophes, no exclamation marks.
