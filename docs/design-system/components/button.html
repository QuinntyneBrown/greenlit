Button

Buttons trigger an action on the current page. Seven variants, three sizes, every state, in both themes.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

A button does something: saves a form, confirms a request, opens a dialog, paints a day. Something that takes you somewhere else is a link, even when it is styled like a button (<a class="btn">).

Greenlit uses five general variants (primary, secondary, ghost, link, danger) and two that exist for one job each: approve, the manager's green confirm action in a request row, and inverse, the translucent button that sits on the dark selection bar. Use at most one primary button per view or dialog.

Anatomy

  1. Leading icon (optional)1.25em square, inherits the label colour, aria-hidden.
  2. LabelA verb phrase in sentence case. It is the accessible name.
  3. ContainerHeight from --control-height-*, --radius-md corners, 1px border, padding from the spacing scale.

Variants

Variants change emphasis, not meaning. Choose by how much attention the action deserves on this view.

Emphasis from highest to lowest. Danger is reserved for destructive confirmations.
HTML
<button class="btn btn--primary" type="button">Request days</button><button class="btn" type="button">Cancel</button><button class="btn btn--ghost" type="button">Edit</button><button class="btn btn--link" type="button">Learn more</button><button class="btn btn--danger" type="button">Remove member</button>

Sizes

Medium is the default. Small lives in table rows, request rows and toolbars; large is for the auth screens, where the button is the whole point.

Heights: --control-height-sm/md/lg; horizontal padding --space-3/4/6; font --font-size-sm/md/lg.
HTML
<button class="btn btn--primary btn--sm" type="button">Small · 32px</button><button class="btn btn--primary" type="button">Medium · 40px</button><button class="btn btn--primary btn--lg" type="button">Large · 48px</button>

States

Every variant has the same six states. Pointer and focus states are forced here with data-state so they can be reviewed without a mouse; real pages get them from :hover, :focus-visible, :active, :disabled and aria-busy.

Both themes

  • Loading keeps the button's width, hides the label, shows a spinner, sets aria-busy="true" and ignores clicks. Use it on the button that was pressed (the dialog's confirm button), not on the whole form.
  • Disabled uses the native disabled attribute: 50% opaque, not focusable. In a form, prefer leaving the submit enabled and explaining the problem on press.
  • Pressed (toggle) uses aria-pressed and belongs to the segmented control, the sheet cell and a single on/off toggle such as "Most days left first" on the year page (gl-button [pressed]), which takes the accent fill while on. It does not belong to ordinary action buttons.

Responsive behaviour

  • Below --layout-breakpoint-md (768px) the one primary action of a form or auth card becomes .btn--block; secondary actions stack beneath it.
  • In dialog and drawer footers the buttons stay on one row and wrap when it is too narrow; the primary stays last (rightmost, or bottom once wrapped).
  • Medium and large buttons exceed the 44px comfortable target. Small (32px) is used only inside rows that are themselves tappable, with at least 8px between neighbours.
  • Labels never truncate. A label that wraps at 360px is too long: shorten the verb phrase.

Theming

The button reads semantic tokens through four component tokens (--btn-bg, --btn-fg, --btn-border, --btn-bg-hover) that each variant overrides. A theme changes the semantic tokens; a product re-skin overrides the component tokens; neither edits .btn.

/* Re-skin primary buttons for a partner theme without touching .btn */
[data-theme="partner"] .btn--primary { --btn-bg: var(--color-accent); --btn-fg: var(--color-fg-on-accent); }

In the dark theme the primary button inverts: the accent becomes near-white and the label near-black, so the pair stays above 15:1. Approve flips its label with --color-fg-on-brand-strong (white on dark green in light, ink on light green in dark).

Accessibility

Role and pattern

Native <button type="button"> (or type="submit" inside a form). A link styled as a button stays an <a href>. Never a <div> with a click handler. No ARIA role is needed.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order.
Enter, SpaceActivates the button. Space fires on key up, so a mis-press can be cancelled by moving away.
EscNo effect on the button. A loading button cannot be cancelled with Esc, so offer a separate Cancel for long actions.

Focus

The shared ring (--focus-ring-width solid --color-focus-ring, offset --focus-ring-offset) shows on :focus-visible only, so pointer clicks do not draw it. The offset gap shows the surface colour, which keeps the ring at least 3:1 against both the button and the page.

Labelling

The visible label is the accessible name. Icon-only buttons set aria-label with the verb and the object when several are on screen ("Remove holiday Midsummer") and are described on hover and focus by a tooltip where the icon is not universal. Loading buttons keep their name and add aria-busy="true"; announce the outcome in a live region, not by changing the label.

Motion

Background and border transition over --duration-fast; the active state moves the button 1px. Both collapse under prefers-reduced-motion because the motion tokens go to zero. The loading spinner keeps turning: it is a status indicator, not decoration.

Touch

Medium (40px) and large (48px) meet the 24px minimum (WCAG 2.5.8) and approach or exceed the 44px comfortable size. Small (32px) is used only where the surrounding row is also tappable, with 8px gaps.

Content

  • Labels are verb phrases in sentence case: "Request days", "Invite member", "Confirm 5 days". Never "OK", "Yes", "Submit" or "Click here".
  • Say what happens, with the object when context does not: "Remove member" in a dialog, "Remove" in a row beside the name.
  • Destructive labels name the loss: "Remove Imani", "Delete holiday", not "Confirm".
  • Keep labels to three words where possible. Use the vocabulary of the product: team, member, day, holiday, manager.
  • Loading does not change the label. Progress text goes in a live region ("Saving…").
