Tabs

Tabs switch between views of the same list on one screen, such as Pending, Approved and Declined requests.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

.tabs is a row of .tab buttons with role="tab"; the selected tab has aria-selected="true" and a 2px brand underline. Use tabs when the views share one data set and one page (the Requests screen filters by status, each tab with its count) and only one is visible at a time.

Do not use tabs for navigation between pages: that is the app navigation. Do not use them to pick a paint colour or a mode: that is a segmented control. Keep tabs to three or four; more means a different component.

Anatomy

  1. Tab.tab button, role="tab", label font, 44px tall, muted until selected.
  2. CountOptional subtle number after the label, tabular figures; part of the tab's name.
  3. Selection indicator2px brand underline (::after) on the tab with aria-selected="true"; the text also turns to --color-fg-accent.

Variants

One style; the content of the tab list varies.

Sizes

Not applicable: tabs have a single 44px height so they are always a comfortable target.

States

Hover can be forced with data-state="hover"; focus uses the shared data-state="focus". Selection is a real attribute.

PartDefaultHoverFocusSelectedSelected + focus
Tab

Both themes

  • Disabled tabs are not used: a view with no content shows an empty state in its panel instead.
  • Overflow: the row scrolls horizontally (overflow-x: auto, scrollbar hidden) when the tabs do not fit.

Responsive behaviour

  • The tablist is a single row at every width; it scrolls horizontally with touch or trackpad when the labels do not fit (360px fits three short tabs with counts).
  • On the Requests screen the tablist shares a row with the selection controls (.toolbar-row); below 640px that row wraps and the controls drop beneath the tabs.
  • Tab labels never wrap (white-space: nowrap). Shorten the label rather than wrapping it.
  • The panel below is full width; do not put tabs in a narrow column.

Theming

Selected text uses --color-fg-accent (dark green in light, light green in dark); the indicator is --color-brand (the base rule uses --color-accent and a later override swaps it to brand); the row's baseline is --color-border-default.

.tab[aria-selected="true"]::after { background: var(--color-accent); }  /* neutral instead of brand */

Accessibility

Role and pattern

WAI-ARIA APG Tabs pattern with manual or automatic activation: role="tablist" > role="tab" buttons controlling a role="tabpanel". Use roving tabindex: only the selected tab is in the tab order (tabindex="-1" on the others).

Keyboard

KeyAction
TabMoves focus into the selected tab, then to the panel (the panel has tabindex="0").
Arrow Left / Arrow RightMoves focus to the previous or next tab, wrapping at the ends; selects it (automatic activation).
Home / EndMoves to the first or last tab.
Space / EnterActivates the focused tab when activation is manual.

Focus

The shared ring is drawn around the tab button. The ring is not clipped by the tablist because overflow-x: auto is paired with enough vertical padding from the button's own 44px height.

Labelling

aria-label on the tablist names the set ("Request status"). Each tab has an id referenced by the panel's aria-labelledby; each tab's aria-controls names the panel. The count is inside the button, so the name is "Pending 4".

Motion

The indicator's background colour transitions over --duration-fast; nothing slides. Reduced motion removes even that.

Touch

Each tab is 44px tall with 12px padding; at three tabs they stay a comfortable size at 360px. Swipe scrolls the row when it overflows.

Content

  • Labels are one word and a plural noun or a status: Pending, Approved, Declined.
  • Counts are numbers only, no parentheses or brackets.
  • Keep the order stable across visits and keep the most useful tab first (Pending).
  • The panel heading, if any, does not repeat the tab label.
