Component · Data display

Request row

One request on the manager's Requests page: who, which days, the note, anything that clashes, and the decision. Stacks on a phone, four columns from 768px.

Overview

A request row is how the manager sees a member's request for days off: the member and the range, the note they wrote, a hint about overlaps with others, and the two possible decisions. Members see the same row without the person and checkbox, with the request's status and a Cancel button. The row opens the request detail dialog when the name is pressed.

The page lists rows in a .request-list inside a card, under tabs for Pending, Approved and Declined. For general-purpose lists, use list; for tabular comparison use table. The approve button is the green approve button; the decided status is the .req-status from badge and status. Bulk approving uses the checkboxes and the selection bar pattern's cousin on the page header.

Anatomy

  1. Checkbox.request-row__check: selects the row for bulk approval. Hidden below 768px. Labelled "Select Ana Ruiz's request".
  2. Who button.request-row__who: avatar, name and range in one button that opens the request detail dialog.
  3. Note.request-row__note: the member's note in quotes, truncating to one line.
  4. Meta.request-row__meta: overlaps with others, or "No overlaps", or the decision dates.
  5. Actions.request-row__actions: Decline and Approve, or the final status.

Responsive behaviour

  • Below 48rem (768px): the row is a flex column with a 12px gap. The checkbox is hidden, the who button is first, then the note and meta, then the actions row, which wraps. The title and sub line truncate with an ellipsis; the note truncates to one line.
  • 48rem and up: the row is a four-column grid: checkbox (auto), who (1.1fr), note and meta (1.4fr), actions (auto) with a 20px gap, vertically centred. The actions align to the end.
  • Bulk selection is a desktop feature: the checkbox column exists only in the grid layout. A phone manager approves rows one at a time.
  • Each column has min-width: 0, so long names and notes truncate rather than widen the page. At 360px nothing scrolls horizontally.
  • The row has no breakpoint-specific text; the same copy reads at both widths. View this page at 360px to see the stacked layout.

Theming

The row is a transparent container separated by --color-border-default. A selected row tints with --color-accent-subtle; sub lines and meta read --color-fg-muted. Decided statuses take the sheet's confirmed and off colours via --dot. The approve button follows its own tokens (--color-brand-strong).

/* Larger gap between columns for a roomier manager view */
.request-row { column-gap: var(--space-8); }

Accessibility

Role and pattern

A list (<ul>/<li>) of rows with ordinary controls: a checkbox, a button and action buttons. There is no composite widget, so every control is a tab stop in reading order. The who button opens a dialog and follows the APG modal dialog pattern; focus returns to it on close.

Keyboard

KeyAction
Tab / Shift+TabCheckbox, who button, Decline, Approve, then the next row.
Space on the checkboxToggles selection.
Enter, Space on who or an actionOpens the detail dialog; declines or approves (decline opens a confirmation dialog).
Esc in a dialogCloses it; focus returns to the opener.

Focus

The shared ring on each control. After Approve or Decline removes the row, move focus to the next row's who button, or the list heading if it was the last, never to the document start.

Labelling

Controls repeat in every row, so each names its row: the checkbox is "Select Cleo Park's request"; buttons read "Decline Cleo Park's request" and "Approve Cleo Park's request" in context (or have an aria-describedby to the title). The range and note are plain text in the who button. The status is the word "Approved", with the dot only as a hint. Announce the decision in a toast live region (toast).

Motion

The row has no motion of its own. Removing a decided row from the list is instant; the toast uses the standard enter motion. Reduced motion removes button transitions.

Touch

The who button spans the identity block (at least 44px tall with the row padding), so it is easy to tap. Approve and Decline are 32px buttons 8px apart, wrapping on a phone rather than shrinking. Bulk selection is desktop-only because the checkbox is 16px.

Content

  • Title: member's full name; sub: range and count: "16–20 Nov · 5 days". Counts use "1 day", "2 days".
  • Note in typographic quotes, as the member wrote it. No note is not shown at all.
  • Meta: who overlaps ("Dev also out 18–19 Nov") or "No overlaps". Never leave it blank on a pending row.
  • Buttons: Decline, Approve; statuses: Pending, Approved, Declined.
  • A member's own row uses the range as the title and "Sent 3 Nov" as the sub.
