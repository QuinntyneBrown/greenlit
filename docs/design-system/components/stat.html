Component · Data display

Stat

One number with its caption: the big days-left figure on a person's page, and the small label-value-delta stat for summaries.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

A stat makes one number the focus. Greenlit has two: the big number on the person page, which answers "how many days does this member have left?", and the small stat (.stat) that pairs a label, a value and an optional change for summary strips.

The big number turns red (data-over) when approving the pending requests would take the member over their allowance, and the caption says so in words. A number that the user edits is a counter. Several related facts in a row are a description list (the .facts bar); many members compared across columns are a table.

Anatomy

  1. NumberDisplay face, extra bold, tabular figures, 1.25 × the 5xl size. Accent green; red with data-over.
  2. CaptionMuted body-small text that states the unit, the period and any warning in words.

  • Over uses data-over and a caption sentence. Remove the attribute as soon as the pending requests are decided.
  • Loading uses skeleton shapes of the final size, so the page does not jump when the number arrives.

Responsive behaviour

  • The person header stacks below 48rem: the member's name and avatar first, the big number beneath. From 48rem the two sit on one row, aligned to the baseline.
  • The big number never wraps; at 60px it fits two digits at 360px. Captions wrap beneath it.
  • .stat items live in a cluster; they wrap to a second row when the container is narrow.
  • The .facts-bar that holds a stat stacks below 40rem and becomes a row from 40rem.

Theming

The big number reads --color-fg-accent, which is a deep green in light theme and a light green in dark, and --color-danger-fg when over. Captions read --color-fg-muted. The stat delta uses --color-success-fg and --color-danger-fg.

/* Neutral big number for a read-only member view */
.member-view .big-number { color: var(--color-fg-default); }

Accessibility

Role and pattern

Plain text, not a widget. The value and its caption are adjacent in the reading order ("4, days left in 2026, 2 days over once requests are approved"). When a number is a live total that updates, put it in an element with role="status"; otherwise no live region is needed. There is no APG pattern for static figures.

Keyboard

KeyAction
TabDoes not stop on a stat. Links or buttons near it take the normal order.

Focus

Not focusable. Do not add tabindex to make it reachable; screen readers reach it with reading commands.

Labelling

The caption supplies the unit and period: a bare "4" is meaningless. The over-allowance warning lives in the caption text, with the danger colour as reinforcement (WCAG 1.4.1). Delta direction is written ("+2", "−1"), not only coloured.

Motion

No count-up animation; the number appears at its final value. Skeletons stop under reduced motion.

Touch

Not interactive, so no target applies.

Content

  • Caption = unit + period: "days left in 2026", not "Days".
  • When over, say how: "2 days over once requests are approved".
  • Whole numbers only. Half days are not a Greenlit concept.
  • Use the vocabulary: Allowance, Used, Booked, Requested, Tentative, Left.
  • Deltas state the direction and the reference: "+2 this month".
