Empty state

An empty state explains why a region has nothing to show and offers the next step: an icon, a title, a sentence and up to two actions, in a default, compact and error form.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

Use an empty state when a list, page or region loaded successfully and has no content: no one on the team yet, no requests waiting, no holidays. Its job is to say what is true, why it matters and what to do next. The same component, in its error form, covers a region that failed to load ("We couldn’t load the calendar").

A whole-page failure (404, 403, 500, offline, session expired) is an error page. A region that is still loading is a skeleton. A message inside a form is an inline message. An empty state is never an error unless it has the error modifier, and is never celebratory noise: "Nothing waiting. Everyone's greenlit." is the tone.

Anatomy

  1. Icon badgeA 4rem circle on --color-accent-subtle with an .icon--lg glyph, aria-hidden.
  2. Title.empty__title, H3 style, states what is empty. A heading element (h2 in a region, h1 on a page).
  3. Text.empty__text: why, and what to do, capped at 36ch.
  4. Actions (optional).empty__actions: one primary action and at most one secondary, centred and wrapping.

Sizes

Two sizes: the default fills a page or a large panel (--space-12 block padding), and .empty--compact (--space-8) fits a card, a table body or a settings section. The icon badge is always 4rem and the text is capped at 36 characters wide. For a single line in a small widget, write a sentence of muted text instead of an empty state.

  • Loading is never an empty state: show a skeleton first, then the empty state if the response is empty.
  • Filtered: if a filter hides everything, say so and offer "Clear filters" as the action.
  • Error: keep the region's frame and replace its content; do not leave stale data behind.
  • No entrance animation, so nothing changes under prefers-reduced-motion.

Responsive behaviour

  • The empty state is a centred column at every width. Padding stays at --space-12 by --space-6 (default) or --space-8 by --space-4 (compact).
  • Text is capped at 36ch so lines stay short on desktop; on a phone it wraps to the card width.
  • Actions wrap and centre (flex-wrap: wrap); at 360px two buttons stack. Give the primary action .btn--block only if it is the lone action on a phone.
  • In a card, a table body or a split layout use the compact form so the empty state does not push the rest of the page off screen.

Theming

The badge uses the accent tint (--color-accent-subtle with --color-fg-accent for the glyph); the error form switches to --color-danger-bg and --color-danger-icon. The title uses --text-h3 and the text --color-fg-muted. All values are semantic tokens, so both themes work without overrides.

.empty--info .empty__icon { background: var(--color-info-bg); color: var(--color-info-icon); }

Accessibility

Role and pattern

A static region of content, not a widget: no ARIA role. The title is a real heading (h2 inside a page, h1 when it is the page's main content) so the region can be found by heading navigation. When an empty or error state appears in response to an action, insert it inside a polite live region or move focus to its heading so the change is announced.

Keyboard

KeyAction
TabMoves through the actions in DOM order. The icon and text are not tab stops.
Enter, SpaceActivates the focused action button; Enter follows a link action.

Focus

Actions use the shared ring (button). When an empty state replaces content after a user action (clearing a filter, a failed refresh), move focus to the title (give it tabindex="-1") so keyboard and screen-reader users land on the new content.

Labelling

The icon is decorative and aria-hidden. The title says what is empty in words ("No one on the team yet"), so the tint is never the only signal that something is wrong in the error form. Action labels name the verb and object ("Invite member", "Add holiday", "Try again").

Contrast

Text on surface

Motion

No motion. The empty state appears in place; there is nothing to reduce. Do not add a bouncing or pulsing illustration.

Touch

Actions are medium (40px) or small (32px) buttons with 12px between them (--space-3), centred in the column. The text is not interactive. On phones, prefer medium buttons for the primary action.

Content

  • Title: what is empty, in the product's words: "No one on the team yet", "No holidays yet". For a cleared queue say so warmly and briefly: "Nothing waiting. Everyone's greenlit."
  • Text: why it matters or how it gets filled, then what to do: "Invite your team from Settings to start planning time off." At most two sentences.
  • Error title: "We couldn’t load the calendar"; text: "Something went wrong on our side. Your days are safe, and nothing was changed." Always reassure about data.
  • Actions: the verb that fixes it ("Invite member", "Add holiday", "Try again"). One primary, one secondary at most. Omit actions the person cannot take (a member cannot invite: say "Ask Maya Chen to invite your team").
  • No exclamation marks, no humour about errors, no apologies beyond "couldn’t".
