Form layout

Form layout arranges fields: a responsive grid, fieldsets with legends, an error summary at the top and an actions row at the bottom.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

Greenlit forms are short, single-purpose and read top to bottom: Create team, Invite member, Add holiday, Team settings. This page covers how form fields are placed. .form-grid puts fields in one, two or three columns; fieldset with legend groups related fields; .form-summary is the alert that lists errors; .form-actions holds the buttons.

Use one column unless two fields are naturally a pair (name and e-mail, date and name). In a dialog the actions live in the dialog footer, not in .form-actions. The wider pattern, including validation timing, is on the Forms pattern.

Anatomy

  1. Form summary.form-summary on an .alert--danger with role="alert": count of problems and a link to each field.
  2. Fieldset and legendGroups related fields and names the group. legend uses the label font.
  3. Form grid.form-grid--2: two equal columns from 40rem, one column below; gap --space-4.
  4. Form actions.form-actions: right-aligned, wrapping row; the primary action is last.

Sizes

Not applicable: Layout has no size scale; it follows the viewport width.

States

Layout has three states that change what is on screen.

Pristine

No summary, no errors; the primary action is available (prefer not to disable it).
HTML
<form class="stack" aria-label="Create team" style="width: 100%; max-width: 28rem;"><div class="field"><label class="field__label" for="fl-st1">Team name</label><input class="input" type="text" id="fl-st1" name="fl-st1"></div><div class="form-actions"><button class="btn btn--primary" type="submit">Create team</button></div></form>

Submitting, disabled and read-only

While submitting the pressed button shows aria-busy (see button). A fieldset disabled dims everything (70% opacity) for a read-only view, such as a member viewing team settings.

Responsive behaviour

  • .form-grid is one column by default. .form-grid--2 and --3 take effect from 40rem (640px) with minmax(0, 1fr) columns, so long values never widen the grid. At 360px every form is one column.
  • .form-actions wraps; right-aligned on wide screens. In a card or on an auth screen prefer a single .btn--block primary.
  • Keep the DOM order equal to the reading order: the grid fills left to right, then top to bottom, so put the more important field first.
  • The error summary is full width and sits above the first field in the scroll flow, never fixed to the viewport.

Theming

The grid and actions read only spacing tokens (--space-4 gap, --space-3 between buttons, --space-4 padding above actions). The summary is an alert: --color-danger-bg fill, --color-danger-border edge, --color-danger-fg text, --color-danger-solid for the 4px left edge. Change the density by overriding the gap once:

.form-grid { gap: var(--space-3); }   /* denser forms in dialogs */

Accessibility

Role and pattern

Standard HTML form structure: <form> with an accessible name, <fieldset>/<legend> for groups, labels on every control. The summary follows the "error summary" pattern from GOV.UK and WCAG technique G139/ARIA22: role="alert" with in-page links to the fields.

Keyboard

KeyAction
Tab / Shift+TabFollows DOM order: summary links, then fields, then actions.
Enter (in a field)Submits through the form's default (primary) button.
Enter (on a summary link)Jumps to and focuses the invalid field.

Focus

After a failed submit focus moves to the summary heading (or the first invalid field if there is no summary). The summary links are real <a href="#id"> anchors; the target field receives focus. Focus is never trapped.

Labelling

The form has an accessible name (aria-label or a heading via aria-labelledby). Fieldsets are named by their legend. The summary title states the count ("Fix 2 things to continue") and each list item repeats the field's error text. Disabled fieldsets are announced as unavailable.

Motion

The summary appears without animation so it is announced right away. Nothing in the layout moves.

Touch

Fields are stacked in one column on touch widths; actions wrap with a 12px gap and at least 40px high. Summary links are inline text: keep the list short and use full sentences so each is easy to hit.

Content

  • Summary title: "Fix N thing(s) to continue"; each item is the field's own error sentence, e.g. "Give your team a name".
  • Legends are questions or nouns: "Who is on the team?".
  • Button order: secondary (Cancel) then primary; the primary names the result ("Create team", "Add member").
  • Intro copy under a legend explains what to enter in one sentence.
