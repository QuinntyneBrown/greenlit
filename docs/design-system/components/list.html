List

A vertical run of rows that each describe one thing: a member, a request, a stretch of time off. Plain, interactive and run-list forms.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

Use a list when each item needs a name, a line of context and possibly an action, and the set is short enough to read top to bottom. A person on the team with this month's time off, or the stretches of time off on a member's page, are lists. The semantic element is always <ul> with <li> children, so a screen reader announces "list, 3 items".

When readers compare the same facts across rows (allowance, used, left), use a table. For members with inline editing controls use the member list; for requests with approve and decline use the request row. Both are specialised lists built on the same idea. Key-value facts about a single person are a description list.

Anatomy

  1. Leading visualAn avatar or a status swatch. Decorative, aria-hidden.
  2. Title.list__title: label type. The item's name, and the link when the item navigates.
  3. Meta.list__meta: one muted line, --text-body-sm. States the status in words.
  4. Trailing action or chevronA button or chevron icon; the action is named for the item.

Variants

Three list shapes share the same rules: separated by hairline rules, no outer padding, items end where the container ends.

List rows have no state of their own except the interactive item's hover and its link's focus. Selection and busy states belong to the specialised rows built on lists.

Responsive behaviour

  • Lists are fluid: rows fill the container and the body column (flex: 1; min-width: 0) lets long names shrink instead of pushing the trailing action off screen.
  • There are no media queries on lists. Titles and meta wrap rather than truncate unless the specialised row says otherwise (.request-row__title truncates).
  • .run-list__status keeps a 5rem minimum so statuses align down the column at every width.
  • A trailing button stays on the row; if two actions do not fit at 360px, move the second into a menu.

Theming

Rows read --color-border-default for rules, --color-fg-muted for meta and --color-bg-subtle for the interactive hover. Status swatches in the run list use the sheet tokens through --status-bg, so the colours match the calendar in both themes.

/* A denser list inside a drawer */
.drawer .list__item { padding-block: var(--space-2); }

Accessibility

Role and pattern

Native <ul>/<li> (the list is not a listbox: its items are not selectable options). Interactive rows contain real links or buttons; role="button" on the <li> is never used. Note that list-style: none removes list semantics in some Safari builds; add role="list" only if testing shows it is lost.

Keyboard

KeyAction
Tab / Shift+TabMoves between the links and buttons in rows.
EnterFollows a link or presses a button.
SpacePresses a button; does nothing on a link.

Focus

The link or button inside the row takes the shared focus ring. The row itself is not focusable, which avoids a double stop on rows with both a link and an action.

Labelling

The list gets aria-label or a heading association ("Time off this year"). Each row's trailing action names its item ("Review Ana Ruiz's request"). Leading avatars and swatches are decorative; the status is always in the meta text.

Motion

No motion beyond the global colour transition on hover. Skeleton shimmer stops under prefers-reduced-motion.

Touch

An interactive row is at least 44px tall with its default padding, which meets the comfortable target; keep a trailing button at least 32px and separate from the row's main link by the 12px gap.

Content

  • Title: the thing's name (a member's full name, a date range). Meta: status first, then the count: "Requested · 5 days".
  • Date ranges use an en dash and no year inside the current year: "16–20 Nov".
  • Keep meta to one line. If it needs two, the information belongs in a detail view.
  • Order by what the reader needs next: soonest first for time off, A to Z for people.
  • Never use a list for a single item; show the item directly.
