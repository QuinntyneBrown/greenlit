Component · Sheet and brand

Sheet cell

One day for one member: a coloured square that is also a button, whose status is spelled out by a glyph and an accessible name.

Overview

The sheet cell (.cell) is the atom of the product. It replaces one coloured cell of the Google Sheet: a member's state on one date. Its colour comes from data-status (confirmed, requested, tentative, empty, off); its glyph (✓ … ?) and accessible name carry the same fact so colour is never the only signal (L1-007).

A cell is a <button> where the caller can paint it (their own row, or any row for the manager) and a plain <div> or <span> where they cannot (other people's rows, weekends, holidays). The cell lives in the team grid; the same colours appear as slivers in the year grid and as numbered squares in the month mini. This page also documents the two header atoms that sit above the cells: the column header (.grid-colhead, weekday initial over day number) and the date chip (.date-chip), which marks today.

Anatomy

  1. Weekday initial.grid-colhead first line (aria-hidden); red text when data-off. The header's aria-label ("Thu 9 Jul") is the real name.
  2. Date chip.date-chip: the day number in tabular figures. Today gets aria-current="date" and an ink fill.
  3. Cell.cell[data-status]: --cell-height (40px) tall, at least 24px wide, --radius-sm corners, fill from --status-bg.
  4. Glyph::after in --color-on-status, bold caption size: ✓ confirmed, … requested, ? tentative. Working and off cells have none.

Sizes

The cell is one fixed size per context, not a size scale. Height is the --cell-height token (2.5rem); width is whatever the grid track gives it, never below 1.5rem (the track minimum). Dense views use smaller relatives that share the colours but are not buttons.

Both themes

  • Disabled: a cell the caller may not change is not a disabled button; it is a non-interactive cell (see Read-only). disabled is not used, so the cell's state stays readable by assistive technology.
  • Empty cells are quiet on purpose (--color-status-empty is 6% ink in light, 8% white in dark), so the sheet shows time off first.
  • Busy/saving: painting is optimistic; failures are announced through a toast, not on the cell.

Responsive behaviour

  • The cell has no breakpoint of its own: width comes from the grid track (minmax(1.5rem, 1fr)), height is always --cell-height. At 360px a 30-day month is about 51rem wide, so the team grid scrolls horizontally inside its card.
  • Touch: the minimum 24px by 40px cell meets WCAG 2.5.8 (target size minimum). The --space-0-5 (2px) gap is below the 44px comfortable size, so on a phone painting is done by tap to select then the selection bar, or by dragging across cells, not by many precise taps. There is no pointer: coarse rule today (see drift).
  • Hover brightens by filter: brightness(0.9) only on button.cell; on touch devices that hover state sticks after a tap, which is harmless but means colour alone should never be used to confirm a paint: the glyph appears immediately.
  • In print the colours are kept and the glyphs print too, which keeps a black-and-white copy readable.

Theming

A cell reads --status-bg, which [data-status] sets from the status tokens, and draws its glyph in --color-on-status. Ink is the on-status colour in both themes, because all four status colours are light enough for dark text; do not switch it to white in dark mode.

/* One attribute selector wires every status to every component */
[data-status="confirmed"] { --status-bg: var(--color-status-confirmed); }
/* dark theme only swaps the status tokens: green-500 -> green-400, blue-500 -> blue-400, coral-500 -> coral-400 */

Re-skin the sheet by changing the five --color-status-* tokens in one place; keep every pair at 4.5:1 against --color-on-status (see Accessibility).

Accessibility

Role and pattern

Inside the team grid a cell is a role="gridcell" (or contains a <button> in one) of an ARIA grid. The button's state is in its name ("Ana Ruiz, Tue 14 Jul: Confirmed") and aria-pressed says whether it is in the current selection. Read-only cells use the same name without a button.

Keyboard

KeyAction
TabMoves focus into the grid (one tab stop, the active cell) and out of it.
Enter / SpaceToggles the focused cell into or out of the selection, or paints it with the active paint status.
EscClears the selection.

Focus

The shared focus ring is drawn inside the cell (outline-offset: -2px) so neighbours do not clip it. The ring colour is --color-focus-ring (green-700); see the drift note: on confirmed, tentative and off cells its contrast is below 3:1 and needs a stronger ring on the sheet.

Labelling

Every cell has an aria-label of "Person, Weekday D Mon: Status" and the same string in title for pointer users. Statuses are spoken as Confirmed, Requested, Tentative, Working or Not working. Holidays append their name ("Not working, Company day"). Column headers repeat "Thu 9 Jul" in their aria-label so the initials need not be read. Glyphs are ::after content and are not announced twice.

Motion

Hover brightness changes over --duration-fast; under prefers-reduced-motion the motion tokens collapse and the change is instant. The skeleton shimmer stops (animation: none). There is no paint animation.

Touch

24px minimum width by 40px height passes 2.5.8. Painting works by tap-select plus the selection bar, or by pressing and dragging across cells (pointer events, so it works for touch and mouse). Never require hover to reveal a cell's status; the glyph and the name are always present.

Content

  • Status words are the product's: Confirmed, Requested, Tentative, Working, Not working. Do not invent "Approved", "Pending", "Free", "Off" or "Booked" for a cell.
  • Cell names read as a sentence fragment: person, weekday and date, colon, status. Dates use the short form ("Tue 14 Jul"); the year appears in the grid's name.
  • A holiday keeps the status "Not working" and adds its name after a comma; weekends say just "Not working".
  • Glyphs are exactly ✓ (confirmed), … (requested), ? (tentative). Never add a glyph to working or off cells.
