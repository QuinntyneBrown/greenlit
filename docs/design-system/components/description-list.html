Description list

Terms and their values: a settings summary as two columns, a member's allowance as a row of facts.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

A description list pairs labels with values: the team's name, manager and time zone, or a member's allowance, used and requested days. It is a real <dl> with <dt> terms and <dd> definitions, so assistive technology reads each value with its label.

Use .dl (two columns) for a few key-value lines in a card or dialog. Use .facts (a wrapping row of small groups) with .facts-bar for the summary strip at the top of the person page. For one headline figure with its caption, see stat; for rows of many members compared across the same columns, use a table.

Anatomy

  1. Term (dt)Caption type, muted: the name of the fact.
  2. Definition (dd)Large, semibold, tabular figures: the value.
  3. Group wrapper and unitA <div> around each dt/dd pair is valid in a dl and keeps the pair together when the row wraps. Optional <small> inside the dd holds a unit or note.

Sizes

Not applicable: One size per layout; the value size (<code>--font-size-lg</code>) and gaps come from the tokens.

States

A description list is static: it has no hover, focus, selected or disabled states. Its states are content states.

Responsive behaviour

  • .dl is a two-column grid at every width; the first column is max-content. If a term can be longer than half the screen, switch to .facts, which wraps.
  • .facts wraps: flex-wrap: wrap with a --space-10 column gap and --space-3 row gap, so five groups become two rows at 360px with no media query.
  • .facts-bar stacks vertically below 40rem (640px) and becomes a row with space between at 40rem and up, aligned centre.

Theming

Terms read --color-fg-muted; values inherit --color-fg-default; the bar's rules read --color-border-default. Nothing is theme-specific, so both themes follow from the semantic tokens.

/* Larger values in a dialog summary */
.dialog .facts dd { font-size: var(--font-size-xl); }

Accessibility

Role and pattern

Native <dl>, <dt>, <dd>. Wrapping each pair in a <div> is permitted by HTML. No ARIA role is added; the element is non-interactive and has no APG pattern.

Keyboard

KeyAction
TabPasses over the list: it has no interactive parts. Any link inside a value is a normal tab stop.
Screen-reader list navigationReads each term followed by its definition.

Focus

None of its own. A link or button inside a <dd> takes the shared focus ring.

Labelling

The term is the label: write it so it still makes sense when read out of the layout ("Days requested", not "Req."). Group the list with a heading, or give a standalone one aria-label. Units go in the visible text, not a tooltip.

Contrast

Value on surface
Term (muted) on surface
Term on page canvas
Note in value on surface

Motion

None. Values change instantly when data refreshes; no count-up animation.

Touch

Not interactive, so no target size applies. If a value becomes a link, give it at least the 24px minimum target (WCAG 2.5.8).

Content

  • Terms are short nouns in sentence case: "Allowance", "Time zone". No trailing colon: the layout provides the separation.
  • Values are the data as the sheet shows it: whole days ("17"), dates as "4 Nov", names in full.
  • Put the unit once: in the term ("Days left") or in a small note, not in every value.
  • Order from most to least important, or in the order the same facts appear elsewhere (Allowance, Used, Booked, Requested, Tentative).
