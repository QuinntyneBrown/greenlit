Toast

A toast confirms what just happened without moving the user: a short, transient message on the inverse surface that auto-dismisses unless it reports a failure.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

Use a toast for the result of an action the person just took and does not need to act on: "Requested 3 days", "Invite sent to finn@northwind.studio". It appears at the bottom of the viewport (bottom-right from 640px up), stacks when several arrive, and leaves by itself after 8 seconds. The timer pauses while the pointer or focus is on it. Errors stay until dismissed, and every toast with an Undo keeps it for the toast's whole life.

A toast is not for anything the person must read before continuing: a persistent connection problem or a page-level warning is an alert or banner, a field problem is an inline message, and a decision needs a dialog. Never put the only copy of important information in a toast: it disappears.

Anatomy

  1. Tone iconInfo, success, warning or danger glyph, aria-hidden, coloured by --color-*-icon-on-inverse.
  2. TitleWhat happened, in the past tense, sentence case. It carries the meaning.
  3. Text (optional)One short sentence of consequence or next step, at 90% opacity.
  4. Action (optional)A single underlined text button: Undo or Try again.
  5. Dismiss buttonSquare .close target (24px minimum) with aria-label="Dismiss".
  6. Timer railDecorative 2px line along the bottom edge (.toast__progress), aria-hidden.

Variants

Four tones, always paired with a different icon and a title that states the outcome, so tone is never carried by colour alone. Toasts sit on the inverse surface in both themes; only the icon takes the tone colour.

Sizes

A toast has one size. It fills the region: full width minus --space-4 gutters below 640px, and a fixed 24rem column anchored bottom-right from 640px up. Height follows the content (title, optional text, optional action). Do not add a large variant: if the message needs more room, it belongs in an alert or a dialog.

States

A toast moves through entering (slide-up and fade-in over --duration-base), resting, and leaving (data-state="leaving": fade-out and drop by --space-2). Error toasts are persistent: no timer, no rail, dismiss only by the button.

  • Entering: slide-up over --duration-base with --ease-enter. Under prefers-reduced-motion the duration collapses to ~0, so the toast simply appears.
  • Hover and focus pause the 8-second timer (set by the application, not CSS), so a keyboard user reaching Undo does not lose it.
  • Leaving uses fade-out with forwards fill, so remove the node on animationend.
  • The timer rail (.toast__progress) is a static 2px strip in the shipped CSS; animating its width is the application's job and is decorative only.

Responsive behaviour

  • Below 40rem (640px) the region spans the viewport with --space-4 margins on the left, right and bottom, so toasts are full width.
  • From 40rem up the region is 24rem wide, bottom-right with --space-6 offsets; .toast-region--top flips it to the top.
  • The region sets pointer-events: none so empty space never blocks the sheet; each toast turns pointer-events: auto back on.
  • On a phone the region sits above the selection bar's footprint: raise the region's bottom while a selection bar is open so Undo is not hidden.
  • Toasts are hidden when printing (@media print).

Theming

The toast reads the inverse surface (--color-bg-inverse, --color-fg-inverse), which is dark in the light theme and light in the dark theme, so a toast always stands out from the page. The tone shows only in the icon, through the --color-*-icon-on-inverse tokens, which exist so the icon keeps contrast against the inverted surface. Elevation is --shadow-3; stacking is --z-toast (above dialogs and menus, below tooltips).

/* A partner theme only needs to change the semantic inverse pair */
[data-theme="partner"] { --color-bg-inverse: var(--palette-neutral-900); --color-fg-inverse: var(--palette-neutral-0); }

Accessibility

Role and pattern

Info and success toasts go in a polite live region: role="status" with aria-live="polite" (the ARIA status role; see the APG alert/status guidance). Warning and danger toasts go in an assertive one (aria-live="assertive") so they interrupt; the two regions share one visual stack, newest first. Mount the region empty at page load and insert toasts into it, because live regions announce only changes. A toast that reports a failure carries role="alert" so it is announced immediately. A toast is never focus-trapped and never steals focus.

Keyboard

KeyAction
TabMoves to the toast's action, then its dismiss button, in DOM order after the content that triggered it. Focus pauses the auto-dismiss timer.
Enter, SpaceActivate the focused action (Undo, Try again) or dismiss button.
EscDismisses the newest toast while focus is inside the region.
F6 (optional)Application shortcut that moves focus into the toast region so an Undo is reachable without tabbing through the sheet.

Focus

Focus is never moved into a toast automatically, and a toast never covers the element that has focus: the page scrolls it clear of the stack. Buttons inside it use the shared ring; because the surface is inverse, the ring's offset gap shows the inverse colour, keeping it at least 3:1. When a toast with focus is dismissed, return focus to the control that triggered the action, not to the top of the page.

Labelling

The title is announced first, then the text, then the action label. Keep the title self-sufficient: a screen-reader user may hear only the title. The dismiss button is named "Dismiss" (or "Dismiss: Requested 3 days" when several are stacked). The icon and the timer rail are aria-hidden; the tone is spoken by the words ("couldn’t save"), not the colour.

Motion

Toasts enter with slide-up and leave with fade-out, both over --duration-base. Under prefers-reduced-motion: reduce the global rule shrinks animation durations to 0.01ms, so toasts appear and disappear without movement. Auto-dismiss is a timing, not an animation: it stays, but it pauses on hover and focus, and error toasts have no timer (WCAG 2.2.1).

Touch

The dismiss button is --target-min (24px) square and the action has a taller hit area through block padding; both are separated by --space-3 from the edge. Toasts never require a gesture: no swipe-to-dismiss is the only way out.

Content

  • Title: past tense, what happened, with the object: "Requested 3 days", "Declined Ben’s request", "Invite sent to finn@northwind.studio". Warnings and errors say what did not happen: "We couldn’t save those days".
  • Text: one sentence of consequence or next step: "Maya Chen will be notified." "Your selection is still there." Skip it when the title is enough.
  • Action: a verb: "Undo" or "Try again". Never "OK" or "Close" (there is a dismiss button).
  • Do not apologise in the title and never blame the person. Use the vocabulary of the product: team, member, day, holiday, manager.
  • One idea per toast. If you need two sentences of explanation, use an alert.
