Counter

A counter adjusts one small whole number with minus and plus buttons and shows the value between them. Greenlit uses it for how many people must be in on a working day.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

Use a counter for a small integer where stepping is easier than typing and the range is short: the minimum number of people who must be in on a working day (0 to the team size). The current value is large and always visible, and each press changes it by one.

For a free number (days per year, a negative adjustment, half days) use a text field with type="number". For a larger range or an exact value, also a text field. For a choice among labels use a select or segmented control. A counter is built from two icon buttons and a live <output>; it is not a spinbutton.

Anatomy

  1. Decrease button.btn.btn--icon with a minus icon and a specific aria-label ("Fewer people"). Disabled at the minimum.
  2. Value.counter__value on an <output> with aria-live="polite": heading-size, tabular numerals, 3rem minimum width.
  3. Increase buttonPlus icon, "More people". Disabled at the maximum.
  4. Unit textA muted text-sm span that says what the number counts ("of 7 people in").

One composition. The unit text adapts to the setting.

Sizes

One size. The buttons are standard icon buttons (40px square) and the value uses --text-h2. Use the small button size (.btn--sm) only in dense rows.

States

The buttons carry the states: disabled at the bounds, hover/focus/active as for any button. The value is plain text and has no state.

  • At the minimum or maximum the relevant button is disabled; the value does not wrap around.
  • If saving the new value takes time, show the result in a toast; leave the buttons enabled unless a second press would corrupt the request.

Responsive behaviour

  • The counter is a wrapping flex row (gap: var(--space-3)); the unit text drops below the buttons if the container is too narrow.
  • At 360px the whole counter (two 40px buttons, a 3rem value, and a short unit) fits on one line in a padded card; keep the unit under about 20 characters.
  • Buttons keep their 40px size on touch; do not shrink them to fit.

Theming

The counter has no colour of its own: the buttons use the button tokens and the value inherits --color-fg-default. Its only token is the value's type role, --text-h2, with tabular numerals so the width does not jump between 9 and 10.

.counter__value { font: var(--text-h1); }   /* a larger readout */

Accessibility

Role and pattern

A role="group" named by a visible caption or aria-label, containing two native buttons and an <output>. It is deliberately not the APG Spinbutton: that pattern is for an editable value with arrow-key stepping, which this control does not offer. If the value can be typed, use a number text field instead.

Keyboard

KeyAction
Tab / Shift+TabMoves between the two buttons (disabled ones are skipped).
Enter / SpacePresses the focused button: changes the value by one.
Hold or repeatEach press is one step; there is no press-and-hold repeat.

Focus

The shared ring on the focused button. If a button becomes disabled while focused (the value hit the bound), move focus to the other button so keyboard users are not dropped to the page start.

Labelling

The group is named ("Minimum people in"). Buttons say what they change: "Fewer people", "More people", not "-" and "+". The value is an <output> in a polite live region, so each press announces the new number ("4"), and the unit text ("of 7 people in") follows in reading order.

Motion

Nothing animates; the number changes at once.

Touch

40px buttons separated by a 3rem value: 12px gaps and no accidental double-hit. Well above the 24px minimum; use 48px (.btn--lg) if the control is the focus of a phone screen.

Content

  • The group name says what is counted: "Minimum people in". Button names are the direction plus the unit: "Fewer people", "More people".
  • The unit text gives the context or the maximum: "of 7 people in".
  • Do not show a leading zero or a unit inside the value.
