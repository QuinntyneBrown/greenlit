Theming

How light, dark and customer themes work: the token tiers, color-scheme, and the JSON export.

WCAG 2.2 AAStatus: stable
  • Overview
  • Token tiers
  • How themes apply
  • Both themes
  • Adding a theme
  • tokens.json
  • Do and don't

Overview

A theme is a set of overrides on the semantic token tier. Components never know which theme is active; they read tokens.

Token tiers

TierPrefixExampleWho reads it
Primitive--palette-*, --font-*--palette-green-700Only semantic tokens
Semantic--color-*, --space-*, --radius-*, --shadow-* …--color-accentComponents and pages; themes override this tier
Component--btn-*, --alert-*, --status-bg--btn-bg: var(--color-accent)One component; always an alias of a semantic token

How themes apply

  • Light is :root. Dark is [data-theme="dark"] and, identically, @media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { … } }: the OS preference applies unless a page forces light.
  • Each theme sets color-scheme so native controls, scrollbars and form widgets follow.
  • prefers-contrast: more strengthens borders and muted text; forced-colors: active hands the focus ring and edges to system colours (Highlight, CanvasText).
  • The app keeps the user's choice (system, light or dark) in settings; this site persists it in localStorage and exposes t as a shortcut.

Adding a theme

/* tokens.css — a customer theme: override semantic tokens only */
[data-theme="teal"] {
  --color-accent: var(--palette-teal-700);
  --color-accent-hover: var(--palette-teal-800);
  --color-focus-ring: var(--palette-teal-700);
}
/* then add the pairs to contrast-pairs.json and run check_contrast.py */

tokens.json

{
  "color": { "accent": {
    "$type": "color",
    "$value": "{palette.gray.900}",
    "$extensions": { "theme": { "dark": "{palette.gray.100}" } }
  } }
}

tokens/tokens.json is generated from tokens.css by tokens_to_json.py in the Design Tokens Community Group format (284 tokens, aliases as {group.token}, dark overrides under $extensions). Engineering generates platform constants from it; never edit it by hand.

Do and don't

  • Do build a theme from roles. Don't invert light values: dark surfaces lighten as they rise and accents flip.
  • Do test every pair in the new theme. Don't ship a theme with failing pairs.
  • Don't branch on theme in a component. If a component needs a different value in dark mode, it needs a new semantic token (as --color-info-icon-on-inverse did for toasts).
