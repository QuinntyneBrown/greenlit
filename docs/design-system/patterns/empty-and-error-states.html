Pattern

Empty and error states

What to show when there is nothing to show, when the list is filtered to nothing, and when something fails.

WCAG 2.2 AAStatus: stable

  • When to use which
  • Structure
  • States
  • Responsive behaviour

Overview

An empty or failed region is a moment where a manager can get stuck, so it must answer three questions: what is this, why is it empty or broken, and what do I do now. Greenlit uses one component, empty state, for the first two and error page for whole-screen failures, plus alerts and inline messages when the rest of the screen is still usable.

When to use which

SituationPatternAction offered
Brand-new team, no membersEmpty state with the logo markOpen settings (manager) / nothing (member)
List is empty because nothing is pendingCompact empty stateNone
Filter or search matches nothingCompact empty state, names the filterClear the filter
A region failed to load, rest of page fineEmpty state, empty--errorTry again
Whole screen failed (500)Error page in the app shellTry again, Back to calendar
Unknown route (404)Error pageBack to calendar
No permission (403)Error page that names who can do itBack to calendar
Session endedBare-shell pageSign in again
Network lostBanner, content staysNone; reconnects itself
  • If any useful content remains, prefer a banner or inline message over replacing the page.
  • Empty is not an error. Do not use the danger tint unless something broke.

Structure

Every empty or error state has the same four parts: an icon that is decoration, a title that names the state, one sentence of explanation, and at most two actions. Only the icon colour and the action change.

  • While a retry runs, the Try again button is busy; the message stays so the page does not flash.
  • If the retry fails again, change the sentence ("Still can't load it. Check your connection.") rather than repeating it.

Responsive behaviour

  • 360px: the block is centred, padded --space-6 on the sides; actions stack and the primary is first in the reading order.
  • 768px: actions sit side by side; the text measure is capped at about 36ch.
  • 1024px and up: the empty state is centred in its region, not in the viewport, so the topbar and navigation stay visible.
  • The compact variant is used wherever the region is under about 20rem tall.

Accessibility

  • The title is a real heading at the next level in the page (h2 in a region, h1 when it is the whole page). The icon is aria-hidden.
  • When an error replaces content after a user action, move focus to the title (tabindex="-1") or announce it with role="alert"; on first page load do neither, the heading is read in order.
  • After Try again succeeds, move focus to the new region's heading.
  • The state is never carried by the icon colour alone: the title says "couldn't load".
  • Actions are real buttons or links in reading order after the text.

Content

  • Empty formula: what this place is for, then the next step. "No requests waiting. When a member requests time off, it appears here for you to confirm."
  • Error formula: what happened + why (if known and useful) + what to do + what was kept. "We couldn't load the calendar. Something went wrong on our side. Your days are safe, and nothing was changed."
  • Title: a short statement in sentence case, with no full stop.
  • Do not blame the user or the browser. Do not say "Oops". Do not show raw error codes; put a reference id in small text only for server errors.
  • Use the domain words: team, member, day, holiday, manager.
